# 使用场景

这些场景使用同一套飞书入口和原生 CC 会话，不需要安装额外的业务框架。选择合适的资源与权限即可；模型能力和外部服务权限仍需实际验证。

## 个人助手

只配置自己的私聊，将 `groups` 保持为空。`projects` 中定义一个资源配置单元，维护者可以是私聊使用者本人。无需源码目录、CI 或业务操作。

```json
{
  "projects": [{ "id": "assistant", "maintainers": ["ou_example_owner"], "permissionMode": "default", "actions": [] }],
  "groups": [],
  "dms": [{ "userId": "ou_example_owner", "projectId": "assistant" }]
}
```

这是需要合入主配置的片段，不是独立运行配置。`default` 会对未预授权操作询问，不等于禁止所有写入的只读沙箱。

## 资料整理与文档协作

可以直接发送附件，或将获准使用的文档目录设为 `seedDir`。首次建立会话工作区时复制资料，后续不会自动覆盖本地修改；源目录更新也不会自动同步到已有会话。

群聊配置示例见 [config.example.json](../examples/config.example.json)。只希望处理明确提问时，把 `limits.backgroundMessages` 设为 `0`；需要讨论背景时再启用有界缓存，并告知参与者。

不要求资料必须是代码。提供 `seedDir` 时实现会创建本地 Git baseline 记录修改，但它不是知识库检索服务，也不会自动接入远端文档。远端资料通过获准的工具或固定操作访问。

## 协作开发

将干净的源码目录作为初始资料，按需配置 `trustedConfigDir` 和 `allowedTools`。同群成员可共同补充信息；独立工作由 CC 判断是否使用原生子代理。

每个聊天有独立工作区，多个群使用相同项目配置不表示它们共享聊天记录。先确认项目脚本可信，再预授权测试命令；不要为减少审批直接允许所有 shell 操作。

默认 `acceptEdits` 减少普通文件编辑的确认。发布、部署和修改受保护资源应使用明确的服务权限及审批。

## 查询与业务操作

通过 `actions` 连接可信 CLI 或固定执行器，只开放指定的资源、参数和环境变量。七个[操作示例](project-actions.md)覆盖构建状态、代码提交和文档／表格操作，也可以使用其他经过审核的执行器。

只读声明应与执行器实际行为一致；外部写操作逐次审批。进程停止不代表外部服务已回滚，未知结果需先检查远端状态。

## 共同边界

模型地址和 ID 不绑定供应商，但必须满足 Claude Code 所需接口与工具语义。时间跟随部署环境，模型回复跟随请求语言；内置操作提示目前主要为中文。

原生进程运行在同一服务账户下。多会话的逻辑分离不适合把相互不信任的人放在同一执行账户中；所需信任范围不同，应拆分服务部署与系统权限。
