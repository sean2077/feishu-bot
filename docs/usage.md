# 使用场景

这些场景使用同一套飞书入口和原生 CC 会话，不需要额外的业务框架。选择合适的资源与权限即可；模型能力和外部服务权限仍需实际验证。

## 个人助手

只配置自己的私聊，将 `groups` 保持为空。`projects` 中定义一个资源配置单元，维护者可以是私聊使用者本人。无需源码目录、CI 或业务操作。

```json
{
  "projects": [{ "id": "assistant", "maintainers": ["ou_example_owner"], "permissionMode": "default", "actions": [] }],
  "groups": [],
  "dms": [{ "userId": "ou_example_owner", "projectId": "assistant" }]
}
```

这是需要合入主配置的片段。`default` 会对未预授权操作询问，不等于禁止所有写入的只读沙箱。获准私聊用户直接发消息，不需要 @。

## 资料整理与文档协作

可以发送附件，或将获准使用的文档目录设为 `seedDir`。首次建立工作区时复制资料，后续不自动覆盖修改；源目录更新也不会自动同步到已有会话。

群聊配置见 [config.example.json](../examples/config.example.json)。群和作者都须获准，且默认必须明确 @；只回复机器人而没有 @ 不触发。只有你和机器人的小群可在该群设置 `mentionOptional: true` 免除 @，群和作者授权仍生效。`members` 留空仅允许维护者。

默认 `limits.backgroundMessages = 0`，不缓存或预注入非 @ 群消息。需要前文时，Agent 使用当前聊天限定的 `read_chat_history` 按需获取。必须具备飞书消息读取权限，工具结果仍排除未授权作者。主动启用非零背景缓存属于可选行为，应事先告知参与者。

富文本中的图片和附件使用 Go 平台适配层解析；缺失资源 key 或未支持内容会明确提示重新发送，不把只剩正文的消息当作完整输入。引用和历史中的不完整内容也有标记，不自动展开合并转发。详见[原始消息格式](raw-messages.md)。

连续截图可选开启[多图合批](image-batches.md)：例如 `imageBatchMs: 800` 等待固定 800 ms，默认 0 不等待。只合并同作者、同会话、相同引用／线程关系的连续独立图片；每条群图片独立满足触发条件（默认明确 @；`mentionOptional` 群按作者授权），不把随后无 @ 的图吸入上下文。富文本配图仍按一条完整消息处理，不与邻近图片拼接。每张来源单独保存；任一下载失败或超限时整批不提交。没有配置视觉能力的模型不能仅靠合批获得视觉能力。

资料不必是代码。提供 `seedDir` 时会创建本地 Git baseline 记录修改，但它不是知识库检索服务。远端资料通过获准的工具或固定操作访问。

## 协作开发

将干净源码作为初始资料，按需配置 `trustedConfigDir` 和 `allowedTools`。同群获准成员可在工作期间继续 @ 补充信息，所有线程进入同一主会话；独立工作由 CC 判断是否使用原生子代理。

显式补充使用 `/btw 补充正文` 或 `/ps 补充正文`。例如先发送“检查测试失败原因”，运行中另一位获准成员发送“/btw 优先核对 Windows，暂时不要改公共接口”。两条输入保留各自作者与 UUID，答案沿用原任务卡片。空参数给出用法，没有前台任务则拒绝，不新建任务。普通忙时消息仍保留原来的原生输入行为。

`/btw /new` 与 `/ps /compact` 的正文都是字面补充，不执行管理命令；补充也不能批准工具或回答某个请求。已有 compact 边界会阻止后来的补充越过；目标先结束时，未发送补充取消，而不是在压缩后执行为新任务。收到“已交给原生”只表示进入输入流，不是模型已理解。停止、切换及重启规则见[运行中补充](supplements.md)。

每个聊天有独立工作区，多个群使用同一项目配置不表示共享聊天记录。先确认项目脚本可信，再预授权测试命令；不要直接开放任意 shell 来减少审批。

默认 `acceptEdits` 减少普通编辑的确认。发布、部署和修改受保护资源使用明确的服务权限及审批。

## 追问卡片重复点击

Go 适配层按平台事件／投递身份去重。群里选择只通过仅操作人可见的提示反馈，不刷新共享卡片，也不公开个人勾选；私聊卡片会显示当前选择。单选点击同一项保持选中，点击其他项改选；多选逐项切换。选择状态按操作者分离，第一位提交者生效。结束后的请求不会被迟到按钮重新激活。

卡片更新失败或客户端仍显示旧卡片时，不要不断点击同一按钮或重新发送原任务。在**原聊天**中发送 `/answer <请求ID> <回答>`；群里默认仍须明确 @ 本机器人，`mentionOptional` 群按该群配置。单题可以直接给出自由文本，如 `/answer 00000000-0000-4000-8000-000000000000 我的回答`。多题须使用 JSON，键为卡片中的**完整问题原文**，例如 `/answer 00000000-0000-4000-8000-000000000000 {"问题一":"回答一","问题二":"回答二"}`。该操作只对当前聊天中尚未结束、且由获准作者发起回答的追问有效，不会批准受保护工具操作。

回归覆盖卡片请求归属、重复投递和刷新边界；真实手机与桌面仍须分别验收。客户端缓存旧按钮或刷新失败时，使用上述 `/answer` 恢复。历史 TypeScript SDK 去重问题的背景见[跟踪问题](https://github.com/sean2077/feishu-bot/issues/63)；Go 版不再依赖该 SDK。

## 状态与恢复

`/help` 按对话、查看和管理分组显示命令。`/status` 默认显示中文状态，分别列出排队、已交给原生、已消费待结果、结果未知的输入，以及待回答事项和待交付输出。后台活动为未知时不会显示为零；未确认退出时也不会提示可以新建替代进程。

`/sessions` 显示最近 20 个历史会话，并额外保留当前选择的旧会话，最多 21 条。列表时间明确标注 UTC。用 `/rename 发布检查` 给当前会话命名，`/rename -` 清除名称。同一聊天的名称不区分大小写且不能重复；不同聊天可使用相同名称。名称为 1–80 个字符，不包含控制字符。

`/resume` 接受本聊天的名称、完整会话 ID，或至少 6 位的唯一 ID 前缀，例如 `/resume 发布检查`。短 ID 匹配多个会话时会拒绝并要求更长 ID，不任意挑选。命名与恢复均由维护者或私聊本人操作；恢复会先停止当前运行，选中后仅下条消息恢复上下文，旧后台任务不会自动重启。每个聊天仍只有一个当前会话。

维护者的 `/sessions` 回复在最近 5 个历史会话旁提供“恢复”按钮。确认后会停止当前运行、取消未交付输入，再选择该历史会话；点击按钮本身不启动模型。按钮同时绑定原列表所属的当前会话、目标历史会话、消息及版本；会话已切换或目标不属于本聊天时拒绝执行。普通获准成员仍可查看文字列表，`/sessions --json` 保持机器可读输出。

没有收到回复或文件时，先看 `/outputs`，不要先让模型重做任务。它显示最近 20 条未完成交付，不显示回答正文或服务器文件路径。结果未知的卡片或文件可能已在飞书接收，先核实再由维护者（私聊本人也可）执行 `/retry-output 输出ID`。明确失败或自动重试预算耗尽的记录显示“自动重试已暂停”；处理诊断中的原因后也可明确补发。补发只处理保存的输出，不重新调用模型；明确补发仍可能产生重复消息。正在发送的记录不应重复操作。

查看命令不会创建原生会话或启动模型，也不会隐式补发。诊断脚本可使用 `/status --json`、`/sessions --json`、`/outputs --json`、`/usage --json`；旧版依赖默认 JSON 的脚本应加上该参数。`status.inputs` 分开报告四种输入状态，`pendingOrUnconfirmed` 包含结果未知的输入。`outputs --json` 返回有限元数据及安全说明，不提供回答正文或任意错误原文。空输出列表只表示没有待交付记录，不代表所有输入都已完成。

`/status --json` 的 `outboxStates` 按状态统计本聊天的交付记录，`cardSnapshots.count` 与 `cardSnapshots.bytes` 统计本聊天保存的原生卡片快照条数和 UTF-8 字节数。这些是逻辑记录大小，不是数据库／WAL 文件大小或进程内存；部署整体大小由 `doctor` 报告。`/outputs` 区分明确拒绝、自动重试预算耗尽、限流等待和模型已结束但文件待交付。维护者可见脱敏并截短的诊断（含可用的错误码和 request ID）、失败次数与最早自动重试时间；普通成员只看概括原因。JSON 对应字段为 `reason`、`retryCount`、`retryAfter`、`nativeTurnEnded` 和 `filePending`，`retryAfter` 为 UTC 毫秒时间戳，0 表示没有已保存期限。

## 会话模型配置

管理员可以在主配置中声明少量命名配置；`/model` 或 `/profile` 列出可用名称、模型 ID、轻量模型 ID 和 effort。`default` 始终对应部署的 `model` 配置。下面是合入主配置的示例，模型 ID 须替换成服务实际支持的值：

```json
{
  "modelProfiles": {
    "fast": { "model": "your-fast-model-id", "effort": "medium" },
    "careful": { "model": "your-main-model-id", "smallModel": "your-fast-model-id", "effort": "high" }
  }
}
```

名称须以小写字母开头，后接小写字母、数字、`_` 或 `-`，最多 32 个字符；最多配置 32 项，`default` 是保留名称。省略 `smallModel` 时使用该配置的 `model`。`model.effort` 可设置部署默认值，命名配置省略 effort 时继承它；显式 `auto` 请求原生默认行为。配置只改变原生模型选择与 effort，不提供聊天内的凭据、服务地址或权限修改。

在当前聊天发送 `/model careful` 选择配置，`/model default` 恢复部署默认值。群聊仅维护者可选择，私聊本人可管理自己的会话；获准成员均可查看。选择持久化到本会话，其他聊天不受影响。新建会话从 `default` 开始，恢复历史会话会使用它保存的选择；配置被管理员移除时不会静默换模型：网关保留已保存输入、停止自动重试并只提示一次，须明确选择可用配置或 `default`（或恢复管理员配置）后继续。

切换等待已确认的安全边界：前台输入、审批、正在进行的文件和回复交付操作、原生后台工作以及监控全部结束后，停止旧热进程，按同一原生会话 ID 恢复。已经保存但尚未确认送达的输出仍由交付队列处理。忙时的新普通输入会等待切换，`/btw` 和卡片表单仍可补充原前台任务，但不能越过已排队的 compact。后台状态未知或停止未确认时保留原进程名额；切换不会强制终止它。下一条输入才启动使用新配置的原生进程。

若选择配置恰好与原生进程冷启动并发，引发这次启动的首条输入（或完整图片批次）会先用已启动的配置完成，后续输入再等待切换。这样不依赖首条输入之前尚未出现的 idle 通知，也不会把未知后台状态当成空闲。

模型通过原生 `--model` 参数与对应环境变量选择；effort 使用原生 `CLAUDE_CODE_EFFORT_LEVEL`，允许 `auto`、`low`、`medium`、`high`、`xhigh`、`max`。这些是请求值；各模型支持的档位、组织限制和兼容服务的行为由 Claude Code 与服务决定，网关不模拟额外推理循环。原生选项依据 [Claude Code 模型配置](https://code.claude.com/docs/en/model-config)；当前协议验证版本见[验证与验收](validation.md)。`/model --json` 报告配置选择，`/usage` 的模型字段继续只报告实际收到的原生模型标识。

## 已完成文件

`/artifacts` 显示本聊天最近 20 条已经确认送达的文件记录，包括长回复的完整文本附件。`/artifacts --json` 只输出 ID、文件名、会话、记录时间和可用性，不暴露服务器路径。获准成员可使用 `/artifacts 文件ID` 再次取得文件，操作不会启动模型或重跑原任务。

取回使用交付时保存的冻结副本，不重新读取已经变化的工作区源文件。副本按现有导出保留期清理（目前 7 天）；已清理或不可访问时会提示从原飞书附件查找。取回也检查当前聊天及原始作者的授权，不能传路径或引用其他聊天的文件。新一次文件发送进入正常交付队列；失败后从 `/outputs` 查看，明确补发仍走相同权限与恢复规则。

手动取回与原生任务要求交付的文件分开记录；一次取回失败会保留自己的重试记录，不阻止同会话其他原生回复标记 Done。

## 回复卡快捷操作

回复卡提供“查看状态”“待回答问题”等入口；运行中还可用表单补充当前任务、由维护者停止本轮。补充表单最多 1000 字，更长的正文仍可使用 `/btw`。表单提交保留真实操作者和目标轮次，相同卡片上的同一作者重复提交相同正文只接收一次；正文即使是 `/new` 也只是字面补充。表单没有对应的人类消息气泡，因此使用卡片回调提示接收状态，不给不存在的消息添加 OnIt / Done。

“待回答问题”列出当前会话尚未结束的追问及 `/answer` 入口；最新追问卡上的选项与提交按钮继续沿用逐请求、逐操作者的版本校验。“重试交付”仅处理对应的已保存输出，限维护者或私聊本人；输出已送达或正在发送时不会重发。对结果未知的交付仍会提示可能重复。

快捷操作同时验证签名、当前聊天和作者、当前会话、已实际送达的消息 ID 与卡片版本。停止和补充还绑定原前台轮次，旧按钮不会作用于后来任务；同一可见版本的停止、恢复和重试请求只接收一次。交付再次失败并成功刷新卡片后，新版本允许下一次明确重试；旧按钮仍失效。卡片过期（最后成功绑定后 24 小时）、当前会话已不同或服务重启后，旧快捷操作失效，使用最新卡片或文字命令即可。卡片表单与客户端行为仍须在真实飞书桌面端和手机端验收；离线回归只能证明网关边界。

## 使用量

`/usage` 展示当前聊天所选会话最近一个可去重的原生结果，以及统计起点以来的累计观测。`/usage --json` 提供同样的机器可读数据。查询不启动 Worker、不调用模型、不切换会话，也不读取其他聊天或扫描 transcript。

| 字段 | 含义 |
|---|---|
| `input_tokens` | 原生 CLI 报告的非缓存输入 token，不与缓存读写重复相加为该字段 |
| `output_tokens` | 原生 CLI 报告的输出 token |
| `cache_read_input_tokens` | 原生 CLI 报告的缓存读取 token |
| `cache_creation_input_tokens` | 原生 CLI 报告的缓存创建 token |
| `since` | 本会话开始采集的时间；不声称覆盖此前历史 |
| `latest.models` | 实际主循环响应中的模型标识；没有报告时为 null，不拿配置别名冒充 |
| `cumulative.results` | 按原生结果 ID 去重后的结果数，不是人类消息条数 |
| `cumulative.usage` | 观测范围内可完整累计的字段；存在未报告值或无法识别的结果时保持 null |
| `cumulative.reportedSubtotal` / `missing` | 已报告小计和缺失该字段的结果数，不能用小计冒充完整总量 |
| `historyIncomplete` / `unidentifiedResults` | 升级前历史未完整采集／存在无稳定结果 ID 而无法安全累计的结果 |

缺失或非法数值显示“未知”／null，只有 原生 CLI 确实报告 0 才显示 0。失败结果实际报告的用量也保留；进行中或中断而未返回结果的消耗未知。补充、多图和工具往返不各自制造一条用量记录，而以真正的原生 result 为边界；压缩结果单独标注种类。存在无稳定 ID 的结果时，最近可识别结果并不保证是实际最后一次消耗。

旧版 SDK 0.3.316 与对应 CLI 2.1.316 的持续输入／恢复协议验证表明 `result.usage` 为当前结果主循环的报告，不是跨轮累计；多步工具往返按该结果汇总。它不包含子代理的独立用量。`modelUsage` 等累计快照不再累加，避免重复计数；同轮涉及多个主循环模型时只列出模型集合，不猜分各模型的 token。模型服务报告的名称或 token 也不等同于核验其真实模型身份或账单。

统计保存于 SQLite，原生结果 ID 和会话组成去重键。重启、重复结果及已保存输出补发不重复计数。兼容迁移不把没有稳定 ID 的旧审计补算成完整历史；旧会话显示不完整，新会话从建立时采集。累计使用量不是当前上下文占用；`cost` 和 `contextOccupancy` 保持 null，不估造价格，不添加网关压缩器。相关实测边界见[验证清单](validation.md)。

## 查询与业务操作

通过 `actions` 连接可信 CLI 或固定执行器，只开放指定资源、参数和环境变量。七个[操作示例](project-actions.md)覆盖构建状态、代码提交和文档／表格操作，也可使用其他经过审核的执行器。

只读声明须与执行器实际行为一致；外部写逐次审批。停止进程不能回滚外部服务，未知结果先核对远端状态。`/stop` 保留当前会话，需要主动另起上下文时使用 `/new`。

## 共同边界

`/compact` 使用 CC 原生能力；网关没有另一套自动压缩策略。空闲进程回收和服务重启都按保存的原 session ID 恢复。完整规则见[对话行为](conversation-contract.md)。

模型地址和 ID 不绑定供应商，但必须满足 Claude Code 所需接口与工具语义。原生进程时间跟随部署环境，模型回复跟随请求语言；内置提示主要为中文。

原生进程属于同一服务账户。多会话的逻辑分离不是不可信用户间的强隔离；信任范围不同时应拆分部署与系统权限。
