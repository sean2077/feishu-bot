# 使用场景

这些场景使用同一套飞书入口和原生 Claude Code 会话，不需要额外的业务框架；选择合适的资源与权限即可。本页给出配置片段和操作方法，行为规则以[对话行为](conversation-contract.md)为准；模型能力和外部服务权限仍需实际验证。

## 个人助手

只配置自己的私聊，将 `groups` 保持为空。`projects` 中定义一个资源配置单元，维护者可以是私聊使用者本人。无需源码目录、CI 或业务操作。

```json
{
  "projects": [{ "id": "assistant", "maintainers": ["ou_example_owner"], "permissionMode": "default", "actions": [] }],
  "groups": [],
  "dms": [{ "userId": "ou_example_owner", "projectId": "assistant" }]
}
```

这是需要合入主配置的片段。`default` 会对未预授权操作询问，不等于禁止所有写入的只读沙箱。获准私聊用户直接发消息，不需要 @。

## 资料整理与文档协作

可以发送附件，或将获准使用的文档目录设为 `seedDir`。首次建立工作区时复制资料并创建本地 Git baseline 记录修改，后续不自动覆盖；源目录更新也不会同步到已有会话。资料不必是代码，但这不是知识库检索服务；远端资料通过获准的工具或固定操作访问。

群聊配置见 [config.example.json](../examples/config.example.json)。群和作者都须获准，且默认必须明确 @；只回复机器人而没有 @ 不触发。只有你和机器人的小群可设置 `mentionOptional: true` 免除 @，群和作者授权仍生效。`members` 留空仅允许维护者。显式群可设置 `allowOtherBots: true` 读取其他机器人消息；只有明确 @ 才触发，同一话题同一机器人最多连续 2 轮。`mention_bot` 只对 maintainer 开放，并只接受 `otherBots` 名单中配置了 `openId` 的目标。完整规则见[授权与触发](conversation-contract.md#授权与触发)。

默认不缓存或预注入非 @ 群消息。需要前文时，Agent 使用当前聊天限定的 `read_chat_history` 按需获取；这需要飞书消息读取权限，结果仍排除未授权作者。主动启用非零 `backgroundMessages` 属于可选行为，应事先告知参与者。

富文本中的图片和附件会完整解析；缺失资源或未支持的内容会提示重新发送，不把只剩正文的消息当作完整输入，合并转发不自动展开。见[原始消息格式](raw-messages.md)。

连续截图可开启[连续图片输入](image-batches.md)，例如 `imageBatchMs: 800` 固定等待 800 ms（默认 0 不等待）。群里每张图片仍须各自满足触发条件，富文本配图不与邻近图片拼接。合批不会让没有视觉能力的模型获得视觉能力。

## 协作开发

将干净源码作为初始资料，按需配置 `trustedConfigDir` 和 `allowedTools`。同群获准成员可在工作期间继续 @ 补充信息，所有线程进入同一会话；独立工作由 Claude Code 判断是否使用原生子代理。多人同时处理不同问题的群可配置 `sessionScope: "thread"`，每个新 @ 开启独立[话题会话](conversation-contract.md#话题会话)，在话题内继续 @ 追问。

运行中补充信息使用 `/btw 补充正文` 或 `/ps 补充正文`。例如先发送“检查测试失败原因”，运行中另一位获准成员发送“/btw 优先核对 Windows，暂时不要改公共接口”：两条输入保留各自作者，答案沿用原任务卡片。没有前台任务时补充会被拒绝，不新建任务；`/btw /new` 的正文只是文字。规则见[运行中补充](supplements.md)。

每个聊天有独立工作区，多个群使用同一项目配置不表示共享聊天记录。先确认项目脚本可信，再预授权测试命令；不要直接开放任意 shell 来减少审批。默认 `acceptEdits` 减少普通编辑的确认；发布、部署和修改受保护资源使用明确的服务权限及审批。

## 追问卡片重复点击

追问卡片使用整张表单：每道题可以单选／多选，也可以在“自定义回答”里输入文字，最后一次提交所有题目。每题最多输入 1000 字；非空自定义文字覆盖该题选项，只有空白时回退到所选项，缺少回答会提示题号。可以混用不同题的选项和自定义文字；自定义文字里的 `/new` 等只作为答案，不执行管理命令。

填写中的草稿由当前客户端保留，切换选项不触发共享卡片刷新，也不把甲的选择拼到乙的提交里。第一位通过授权、请求／会话／卡片／版本与截止检查的完整提交生效；重复投递、迟到按钮或另一人的旧提交不能重新激活已结束请求。Go 适配层继续按平台事件／投递身份去重。草稿不是跨设备同步能力，切换客户端前应先完成提交。

卡片更新失败或客户端仍显示旧卡片时，不要反复点击同一按钮或重新发送原任务。在**原聊天**中发送 `/answer <请求ID> <回答>`；群里默认仍须明确 @ 本机器人，`mentionOptional` 群按该群配置。

- 单题可以直接给出自由文本，如 `/answer 00000000-0000-4000-8000-000000000000 我的回答`。
- 多题须使用 JSON，键为卡片中的**完整问题原文**，例如 `/answer 00000000-0000-4000-8000-000000000000 {"问题一":"回答一","问题二":"回答二"}`。

该命令只对当前聊天中尚未结束、且由获准作者回答的追问有效，不会批准受保护的工具操作。手机与桌面客户端的缓存和刷新表现不同，需分别验收（见[验证与验收](validation.md)）。历史 TypeScript SDK 去重问题的背景见[跟踪问题](https://github.com/sean2077/feishu-bot/issues/63)；Go 版不依赖该 SDK。

## 状态与恢复

`/help` 按对话、查看和管理分组显示命令。`/status` 默认显示中文状态，分别列出排队、已交给原生、已消费待结果、结果未知的输入，以及待回答事项和待交付输出。后台活动未知时不显示为零；进程停止未确认时也不会提示可以新建替代进程。

查看命令不创建原生会话、不启动模型，也不隐式补发。

### 会话搜索、命名与恢复

`/sessions [关键词]` 搜索当前聊天的人工名称、原生标题和会话 ID，每页最多 20 条；空格分隔的关键词须同时匹配，最多 8 项、128 字。`%`、`_` 按普通字符匹配，英文使用 SQLite 的 ASCII 大小写折叠。结果依次使用人工名称、原生标题、短 ID 显示；同名原生标题返回多个候选，不替用户猜测。按最后接收的人类输入排序，模型输出、历史重放和管理命令不刷新顺序；没有输入记录的旧会话以创建时间为回退。时间标注 UTC，当前会话 ID 始终单独列出。

下一页使用卡片按钮或 `/sessions --cursor 凭证`。凭证绑定聊天、查询、第一页时间边界和最后一条记录，15 分钟后或服务重启后失效。原列表翻页不会混入后来建立的会话；已有会话收到新输入后可能移到前面，重新搜索即可刷新。`/sessions --json` 返回 `pageLimit`、`query`、`current`、`sessions` 和 `nextCursor`；条目含 `name`、`nativeTitle`、`displayName`、`lastInputAt`。它不是 transcript 全文搜索。

用 `/rename 发布检查` 给当前会话命名，`/rename -` 清除人工名称并恢复自动标题。同一聊天的人工名称不区分大小写且不能重复，不同聊天可以同名；名称为 1–80 个字符，不含控制字符。原生标题在后台同步，只有对应 ACK 才确认成功，超时会明确表示实际标题可能已经改变。`/status` 显示同步状态，`/status --json` 的 `titleSync` 分开报告 `desired`、`confirmed`、`revision`、`state`。进程尚未启动时保留目标，下一次启动对齐，不为改名唤醒模型。

`/resume` 接受本聊天的名称、完整会话 ID，或至少 6 位的唯一 ID 前缀，例如 `/resume 发布检查`；短 ID 匹配多个会话时拒绝并要求更长 ID。原生标题须先搜索再使用候选 ID。命名与恢复由维护者或私聊本人操作；恢复会先停止当前运行，选中后由下一条消息恢复上下文，旧后台任务不会自动重启。每个聊天（话题范围群为每个话题）仍只有一个当前会话。

维护者的 `/sessions` 回复在当前页最多 5 个历史会话旁提供“恢复”按钮。确认后停止当前运行、取消未交付输入，再选择该会话；点击本身不启动模型。按钮绑定原列表所属的当前会话、目标会话、消息及版本，会话已切换或目标不属于本聊天时拒绝。普通获准成员可查看和翻页，但没有恢复按钮。

### 未完成的输入与输出

没有收到回复或文件时，先看 `/outputs`，不要先让模型重做任务。它显示最近 20 条未完成交付，不显示回答正文或服务器文件路径。结果未知的卡片或文件可能已在飞书接收，先核实再由维护者（私聊本人也可）执行 `/retry-output 输出ID`。明确失败或自动重试预算耗尽的记录显示“自动重试已暂停”，处理诊断中的原因后也可明确补发。补发只处理保存的输出，不重新调用模型，但仍可能产生重复消息；正在发送的记录不要重复操作。

`/inputs [--json]` 显示最近 50 条待处理或结果未知的输入：完整输入 ID、作者、会话、状态、等待时长及原因。`/cancel-input 输入ID` 只取消可证明尚未提交的项目；普通成员只能取消自己的输入，维护者可以管理本聊天其他成员的输入。连续图片整批取消；正在交接、已交给原生、已消费或结果未知的输入不能逐条撤回。当前原生任务继续，不标记 Done。

`/discard-output 输出ID` 由本聊天维护者（私聊本人）操作，放弃该轮可核实的依赖交付，包括关联回复、必要文件及此后的同轮补交；原轮结束后才完成的后台结果照常发送。它不停止模型、不撤回已发送或可能迟到的消息、不确认送达，也不标记 Done。组内有正在准备／发送的记录或旧记录依赖无法核实时整组拒绝；独立取回的文件可单独放弃。决定持久保存，重启后不会重新变成待发送。规则见[回复卡与交付](conversation-contract.md#回复卡与交付)。

### JSON 与诊断字段

诊断脚本可使用 `/status --json`、`/sessions --json`、`/outputs --json`、`/inputs --json`、`/usage --json`；旧版依赖默认 JSON 的脚本应加上该参数。

- `status.inputs` 分开报告四种输入状态，`pendingOrUnconfirmed` 包含结果未知的输入。
- `/status --json` 的 `outboxStates` 按状态统计本聊天的交付记录；`cardSnapshots.count` 与 `cardSnapshots.bytes` 统计本聊天保存的卡片快照条数和 UTF-8 字节数。这些是逻辑记录大小，不是数据库／WAL 文件大小或进程内存；部署整体大小由 `doctor` 报告。
- `/outputs` 区分明确拒绝、自动重试预算耗尽、限流等待和模型已结束但文件待交付。维护者可见脱敏并截短的诊断（含可用的错误码和 request ID）、失败次数与最早自动重试时间；普通成员只看概括原因。JSON 字段为 `reason`、`retryCount`、`retryAfter`、`nativeTurnEnded` 和 `filePending`，`retryAfter` 为 UTC 毫秒时间戳，0 表示没有已保存期限。`outputs --json` 不提供回答正文或任意错误原文；空列表只表示没有待交付记录，不代表所有输入都已完成。

## 会话模型配置

管理员可以在主配置中声明少量命名配置；`/model` 或 `/profile` 列出可用名称、模型 ID、轻量模型 ID 和 effort。`default` 始终对应部署的 `model` 配置。下面是合入主配置的示例，模型 ID 须替换成服务实际支持的值：

```json
{
  "modelProfiles": {
    "fast": { "model": "your-fast-model-id", "effort": "medium" },
    "careful": { "model": "your-main-model-id", "smallModel": "your-fast-model-id", "effort": "high" }
  }
}
```

名称须以小写字母开头，后接小写字母、数字、`_` 或 `-`，最多 32 个字符；最多配置 32 项，`default` 是保留名称。省略 `smallModel` 时使用该配置的 `model`。`model.effort` 可设置部署默认值，命名配置省略 effort 时继承它；显式 `auto` 请求原生默认行为。配置只改变原生模型选择与 effort，不提供聊天内的凭据、服务地址或权限修改。

项目可用 `projects[].modelProfile` 声明默认命名配置，值是 `modelProfiles` 中的名称或 `default`；引用不存在的名称时配置加载失败。解析顺序是：会话显式选择优先（包括显式选择 `default`）；从未显式选择过的会话使用项目默认；项目未设置时使用部署默认。下面是把项目默认设为 `careful` 的片段：

```json
{
  "projects": [
    { "id": "assistant", "modelProfile": "careful" }
  ]
}
```

在当前聊天发送 `/model careful` 选择配置，`/model default` 固定使用部署默认值，不再跟随项目默认。选择持久化到本会话，其他聊天不受影响；新建或从未显式选择过的既有会话使用所属项目的默认配置。项目默认改变后，未选中配置的会话在下次原生进程启动或按同一原生 ID 续接时使用新的 `--model`，已有对话历史保留。切换在当前工作安全结束后生效，下一条输入才启动使用新配置的原生进程；权限、等待边界和配置被移除时的处理见[会话配置与快捷操作](conversation-contract.md#会话配置与快捷操作)。

项目默认只改变模型标识和 effort；凭据、`baseUrl`、权限规则和目录仍来自部署配置。`/status` 显示生效的模型配置及来源（会话选择、项目默认或部署默认），`/sessions --json` 的每个会话带 `profile` 和 `profileSource`，`/model` 同时显示项目默认。`doctor` 和 `config explain` 显示项目默认配置名，不显示凭据。

模型通过原生 `--model` 参数与对应环境变量选择；effort 使用原生 `CLAUDE_CODE_EFFORT_LEVEL`，允许 `auto`、`low`、`medium`、`high`、`xhigh`、`max`。这些是请求值；各模型支持的档位、组织限制和兼容服务的行为由 Claude Code 与服务决定，网关不模拟额外推理循环。原生选项依据 [Claude Code 模型配置](https://code.claude.com/docs/en/model-config)，当前协议回归版本见[验证与验收](validation.md)。`/model --json` 报告当前选择、来源、项目默认和可用配置；`/usage` 的模型字段只报告实际收到的原生模型标识。

## 已完成文件

`/artifacts` 显示本聊天最近 20 条已经确认送达的文件记录，包括长回复的完整文本附件。`/artifacts --json` 只输出 ID、文件名、会话、记录时间和可用性，不暴露服务器路径。获准成员可用 `/artifacts 文件ID` 再次取得文件，不启动模型或重跑原任务。

取回使用交付时保存的冻结副本，不重新读取已经变化的工作区文件。副本按导出保留期清理（目前 7 天）；已清理或不可访问时会提示从原飞书附件查找。取回检查当前聊天及原作者的授权，不能传路径或引用其他聊天的文件。新的文件发送进入正常交付队列，失败后从 `/outputs` 查看；它与原生任务要求的文件分开记录，失败不阻止同会话其他回复标记 Done。

## 回复卡快捷操作

回复卡提供「查看状态」入口；运行中可在「更多」里停止本轮或使用表单补充当前任务。旧版本卡片上的「复制」按钮已下线，点击只提示，不再发送文本。

- **查看状态**：在本聊天维护一张可折叠的[状态卡片](terminology.md)，重复点击原地刷新，不追加消息。
- **补充表单**：两行文本域，最多 1000 字，由右下“发送”按钮提交；更长的正文使用 `/btw`。同一作者在同一张卡片上重复提交相同正文只接收一次，正文即使是 `/new` 也只是文字。表单没有对应的消息气泡；原生接收后网关发送回执，显示提交者和完整正文（引用格式，转义 HTML／链接标记），不会给不存在的消息添加 OnIt／Done。
- **待回答**：列出当前会话尚未结束的追问及 `/answer` 入口；最新追问卡上的选项与提交按钮仍按请求和操作者校验版本。
- **重试交付**：仅处理对应的已保存输出，限维护者或私聊本人；输出已送达或正在发送时不会重发，结果未知时仍提示可能重复。成功交付后该按钮随终态刷新移除。

旧卡片过期（最后成功绑定后 24 小时）、当前会话已切换、或后续轮次已开始时，旧按钮失效，使用最新卡片或文字命令即可；完整校验规则见[会话配置与快捷操作](conversation-contract.md#会话配置与快捷操作)。卡片表单与客户端行为须在真实飞书桌面端和手机端验收，离线回归只能证明网关边界。

## 使用量

`/usage` 展示当前聊天所选会话最近一个可去重的原生结果，以及统计起点以来的累计观测；`/usage --json` 提供同样的机器可读数据。查询不启动原生进程、不调用模型、不切换会话，也不读取其他聊天或扫描 transcript。统计语义见[对话行为](conversation-contract.md#使用量)。

| 字段 | 含义 |
|---|---|
| `input_tokens` | 原生 CLI 报告的非缓存输入 token，不与缓存读写重复相加为该字段 |
| `output_tokens` | 原生 CLI 报告的输出 token |
| `cache_read_input_tokens` | 原生 CLI 报告的缓存读取 token |
| `cache_creation_input_tokens` | 原生 CLI 报告的缓存创建 token |
| `since` | 本会话开始采集的时间；不声称覆盖此前历史 |
| `latest.models` | 实际主循环响应中的模型标识；没有报告时为 null，不拿配置别名冒充 |
| `latest.kind` | `turn` 或 `compact`，压缩结果单独标注 |
| `cumulative.results` | 按原生结果 ID 去重后的结果数，不是人类消息条数 |
| `cumulative.usage` | 观测范围内可完整累计的字段；存在未报告值、无法识别或待补存的结果时为 null |
| `cumulative.reportedSubtotal` / `missing` | 已报告小计和缺失该字段的结果数，不能用小计冒充完整总量 |
| `historyIncomplete` / `unidentifiedResults` | 历史或采集记录有缺口／存在无稳定结果 ID 而无法安全累计的结果 |
| `pendingResults` | 原生已报告但仍[待补存](terminology.md)的观测数；大于零时累计总量为 null，已保存小计仍可查看 |
| `cost` / `contextOccupancy` | 始终为 null；不估算价格，也不是当前上下文占用 |

解读时注意：

- 缺失或非法数值显示“未知”／null，只有原生 CLI 确实报告 0 才显示 0。失败结果实际报告的用量也保留；进行中或中断而未返回结果的消耗未知。
- 补充、多图和工具往返不各自产生用量记录，而以真正的原生 result 为边界。`result.usage` 是当前结果主循环的报告，不是跨轮累计，多步工具往返按该结果汇总；`modelUsage` 等累计快照不相加，避免重复计数。同轮涉及多个主循环模型时只列出模型集合，不猜分各模型的 token。
- 存在无稳定 ID 的结果时，最近可识别的结果不一定是实际最后一次消耗。兼容迁移不把旧审计补算成完整历史；旧会话显示不完整，新会话从建立时采集。
- 模型服务报告的名称或 token 不等于核验其真实模型身份或账单。字段语义的协议依据见[验证与验收](validation.md)。

## 查询与业务操作

通过 `actions` 连接可信 CLI 或固定执行器，只开放指定资源、参数和环境变量。七个[操作示例](project-actions.md)覆盖构建状态、代码提交和文档／表格操作，也可使用其他经过审核的执行器。

只读声明须与执行器实际行为一致；外部写逐次审批。停止进程不能回滚外部服务，结果未知时先核对远端状态。`/stop` 保留当前会话，需要另起上下文时使用 `/new`。

## 共同边界

`/compact` 使用 Claude Code 原生能力，网关没有另一套自动压缩策略。空闲进程回收和服务重启都按保存的原 session ID 恢复。原生进程额度或内存阈值已满时，网关保存输入并提示等待，名额释放后自动处理。

模型地址和 ID 不绑定供应商，但必须满足 Claude Code 所需接口与工具语义。原生进程时间跟随部署环境，模型回复跟随请求语言；内置提示主要为中文。

原生进程属于同一服务账户。多会话的逻辑分离不是不可信用户间的强隔离；信任范围不同时应拆分部署与系统权限。
