# 使用场景

这些场景使用同一套飞书入口和原生 CC 会话，不需要额外的业务框架。选择合适的资源与权限即可；模型能力和外部服务权限仍需实际验证。

## 个人助手

只配置自己的私聊，将 `groups` 保持为空。`projects` 中定义一个资源配置单元，维护者可以是私聊使用者本人。无需源码目录、CI 或业务操作。

```json
{
  "projects": [{ "id": "assistant", "maintainers": ["ou_example_owner"], "permissionMode": "default", "actions": [] }],
  "groups": [],
  "dms": [{ "userId": "ou_example_owner", "projectId": "assistant" }]
}
```

这是需要合入主配置的片段。`default` 会对未预授权操作询问，不等于禁止所有写入的只读沙箱。获准私聊用户直接发消息，不需要 @。

## 资料整理与文档协作

可以发送附件，或将获准使用的文档目录设为 `seedDir`。首次建立工作区时复制资料，后续不自动覆盖修改；源目录更新也不会自动同步到已有会话。

群聊配置见 [config.example.json](../examples/config.example.json)。群和作者都须获准，且必须明确 @；只回复机器人而没有 @ 不触发。`members` 留空仅允许维护者。

默认 `limits.backgroundMessages = 0`，不缓存或预注入非 @ 群消息。需要前文时，Agent 使用当前聊天限定的 `read_chat_history` 按需获取。必须具备飞书消息读取权限，工具结果仍排除未授权作者。主动启用非零背景缓存属于可选行为，应事先告知参与者。

资料不必是代码。提供 `seedDir` 时会创建本地 Git baseline 记录修改，但它不是知识库检索服务。远端资料通过获准的工具或固定操作访问。

## 协作开发

将干净源码作为初始资料，按需配置 `trustedConfigDir` 和 `allowedTools`。同群获准成员可在工作期间继续 @ 补充信息，所有线程进入同一主会话；独立工作由 CC 判断是否使用原生子代理。

每个聊天有独立工作区，多个群使用同一项目配置不表示共享聊天记录。先确认项目脚本可信，再预授权测试命令；不要直接开放任意 shell 来减少审批。

默认 `acceptEdits` 减少普通编辑的确认。发布、部署和修改受保护资源使用明确的服务权限及审批。

## 查询与业务操作

通过 `actions` 连接可信 CLI 或固定执行器，只开放指定资源、参数和环境变量。七个[操作示例](project-actions.md)覆盖构建状态、代码提交和文档／表格操作，也可使用其他经过审核的执行器。

只读声明须与执行器实际行为一致；外部写逐次审批。停止进程不能回滚外部服务，未知结果先核对远端状态。`/stop` 保留当前会话，需要主动另起上下文时使用 `/new`。

## 共同边界

`/compact` 使用 CC 原生能力；网关没有另一套自动压缩策略。空闲进程回收和服务重启都按保存的原 session ID 恢复。完整规则见[对话行为](conversation-contract.md)。

模型地址和 ID 不绑定供应商，但必须满足 Claude Code 所需接口与工具语义。时间跟随部署环境，模型回复跟随请求语言；内置提示主要为中文。

原生进程属于同一服务账户。多会话的逻辑分离不是不可信用户间的强隔离；信任范围不同时应拆分部署与系统权限。
