# 飞书原始消息与资源

生产入口使用锁定的 `@larksuite/channel` 归一化，再经应用适配器进入 Gateway。`text` 保留文字和明确 @ 信息；`image` 与 `file` 保留资源 key 和文件名；`post` 使用 SDK 已有的 locale、`content_v2`、图片、`media` 和顶部 `files` 附件区解析。作者、聊天、原消息 ID、引用和线程字段来自平台字段，不从正文中的名字或 @ 文本猜测。

SDK 已支持上述富文本资源，不在网关重复实现渲染器。适配器检查已知格式是否完整：缺失图片／文件 key、损坏 JSON、不支持的富文本元素或文件夹附件会明确拒绝主输入，提示重新发送，不将占位文本或部分正文当作完整任务交给模型。超出单条正文或 12 个资源的输入也明确拒绝，不静默截断。图片连续合批仅适用于独立图片消息，带文字的富文本不是纯图片输入。

授权仍先于网关提示、回执、下载和模型交付。未授权、未明确 @ 的群消息不会收到“不支持”的回复。兼容性检查需要原始内容，但只在内存中检查，转换后的 Message、SQLite、模型输入和日志都不保留完整 raw 对象；提供方错误正文也不进入入站诊断日志。

## 合并转发与引用

Channel SDK 0.7.1 会在自己的策略门之前展开合并转发。应用适配器阻止它自动调用公开的 `rawClient.im.v1.message.get`，将原始方法仅保存在受限的 `Transport.fetch` 闭包内。生产代码不访问 SDK 私有字段，也不开第二条连接。升级 SDK 时必须重跑原始事件接线测试，不能删除这条读取边界。

主输入的合并转发不自动展开，提示在当前聊天重新发送获准使用的原消息或附件。主动历史读取和引用仍检查当前聊天及获准作者；响应中即使出现其他嵌套消息，也只选择请求的、归属合法的消息，不递归跟随。历史中未完整解析的内容使用明确说明和空资源列表，不伪装成已取得完整内容。

已有音视频资源继续按文件交付，没有增加转写或语音功能。卡片仍限 SDK 可解析的内容，不执行原卡片操作。未列明或不完整的格式不代表已获得原始完整内容，必要时请改发文本或文件。

## 验证

原始事件测试使用虚构的 text、post、image、file、引用和线程，经真实锁定 SDK 与生产适配器验证。另从真实 SDK 分发器进入生产订阅函数，再进入真实 Gateway／SQLite，替换的只有网络入口和执行器／飞书传输。测试侧访问分发器仅为注入虚构事件，生产不依赖这些私有字段。

测试先行版本发现两项缺口：图片缺 key 时没有不完整标记，未授权合并转发在网关之前产生一次消息 API 读取；其余四项已有格式与范围用例通过。修复后验证零自动读取，以及显式合法引用仍可读。以上不等于飞书线上长连接、手机或桌面实际消息验收。
