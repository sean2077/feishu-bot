# 原始消息格式

Go 飞书适配层读取平台原始消息字段，再生成稳定的 `core.Message`。作者、聊天、原消息 ID、引用、线程和提及来自平台字段，不从正文中的昵称推断授权。入站事件与历史／引用查询共用同一套内容解析规则。完整原始对象只在内存中检查，不保存到模型输入、数据库或日志。

## 支持范围

| 格式 | 处理 |
|---|---|
| text | 保留正文；只有结构化提及匹配机器人身份才算明确 @，`mentionOptional` 群不要求提及 |
| post | 解析 locale、正文元素、图片与文件；拒绝不能完整理解的主输入 |
| image | 保留图片资源 key；只有独立图片可进入[连续图片批次](image-batches.md) |
| file | 保留文件 key 与名称；下载按配置限制流式进行 |
| audio／video／media | 作为有界文件资源处理；不自动转写或理解音视频 |
| interactive | 仅提取已支持的卡片文字结构；不执行原卡片中的操作 |
| 引用／线程 | 保留平台父消息、根消息与 thread ID；引用内容另经当前聊天和作者校验 |
| 合并转发及其他未支持格式 | 不自动展开或预读；获准触发后明确提示重新发送 |

其他机器人的 text/post 消息只在显式 `allowOtherBots` 群入站，且必须明确 @ 本机器人才触发；未 @ 的消息只作为背景／历史。其内容不参与成员授权，也不能因为带 @ 而获得 action 或审批权限。

## 不完整输入

缺失资源 key、损坏 JSON、未支持元素、文件夹、不完整内容，以及正文超限或资源超过 12 个的输入，不会作为完整任务交给模型；不会只提交剩余文字并假定附件已收到。这类提示在授权之后发出。历史中的不完整内容带说明，不提供未经授权的隐式下载。

## 授权顺序

每条群图片默认都必须自身携带明确 @；`mentionOptional` 群按作者授权独立触发。不能用前一条文本的 @ 为后续图片授权，也不能借用邻近消息进入上下文。富文本中的配图不会和邻近的独立图片合批。收到未授权事件时先丢弃，不读取被引用消息、不下载资源、不加表情。授权规则见[授权与触发](conversation-contract.md#授权与触发)。

## 限制

解析测试使用虚构平台事件与本地网络替身。真实飞书客户端可能以不同结构发送图片、视频、富文本或引用，应按实际事件和两端展示验收（见[验证与验收](validation.md)），不能以解析器测试代替平台验收。
