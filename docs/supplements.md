# 给运行中的任务补充信息

`/btw 正文` 与 `/ps 正文` 是同义的网关命令，只向当前正在执行的前台任务补充信息，不是旁路问答，也不会将同名 slash 命令交给 Claude Code。普通忙时输入保持原有行为。

群里每条补充默认仍须由获准成员明确 @；`mentionOptional` 群按该群配置。私聊用户也须授权。空参数显示用法。没有未完成的前台输入时，命令明确拒绝，不创建会话、不启动 Worker、不调用模型。空闲热进程、仅有后台活动或正在执行 compact 都不算可补充的前台任务。

补充保留独立 UUID、消息 ID、作者、引用、线程和附件，经原有收件、去重、限速和容量控制交付。`/btw /new` 和 `/ps /compact` 的正文是文本，不执行管理命令；也不回答审批、不扩大工具权限。

已排队的 `/compact` 是边界。其后的补充先保存并明确提示等待，不能越过边界；审批卡片仍可操作。补充绑定接收时的具体前台输入，目标结束后尚未提交的补充取消并给出持久恢复通知，不自动跟随下一任务。下载期间也会再次检查目标和授权。卡片表单补充在原生接收后回执提交者和完整正文；回执只表示交付，不代表模型已经读取、理解或执行，原生可能在工具完成后才读取。

原生宿主交接也检查目标：Worker 收到补充时，若已经观察到目标的原生结果，就在写入原生输入队列之前拒绝。网关的状态即使因异步事件处理暂时落后，也不会把这种已知失效的补充继续提交为新任务。只有收到 Worker 的接收确认，才发送补充回执；卡片表单回执包含提交者和完整正文，`/btw` 回执只标注提交者。仅完成管道写入不发回执，重复确认不重复回执。

明确的入队前拒绝会将对应 sent 补充和取消通知一起持久保存，不产生模型结果、用量或 Done；普通输入、已确认接收的补充和其他会话不能被这类事件取消。通知仍按当前授权交付。若拒绝证明尚未持久化就发生故障，恢复时保持结果未知，不推断已经取消或自动重放。这个边界不承诺撤回已经进入原生输入流的内容，也不把接收确认当作模型消费证明。

`/stop`、`/new` 和恢复其他历史会话都会取消尚未交付的补充。Worker 意外退出取消绑定旧运行的待交付补充；服务重启时即使保留相同 session，也不会把这些旧补充恢复成新任务。已经发送而结果未知的输入按原规则标记 uncertain，不自动重放。

补充本身不创建独立 Agent 答案卡。正常回复沿用本轮卡片，按原生结果 UUID 分别完成归属消息；只有实际成功且最终卡片和必要文件全部送达，才添加 Done。取消通知属于系统恢复提示，不是模型答案。
