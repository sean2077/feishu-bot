# 公开发布检查

此清单是公开源码、文档、包和演示材料前的检查范围，也是贡献内容可公开性的唯一说明。它不自动更改仓库可见性，也不证明已完成全部历史清理；可见性由仓库管理员决定。

## 当前文件

检查代码、提示词、配置示例、测试数据、截图和文档中的证据链接。使用虚构 ID、保留示例域名和环境变量引用；不要包含真实密钥、内部地址、私有资源标识、个人路径、组织配置、使用轨迹或需求访谈记录。文档描述功能及限制，测试数据也应是虚构数据。

确认运行配置、`.env`／`service.env`、状态库、transcript、附件、导出、日志和证书私钥未被跟踪。`.gitignore` 只影响未跟踪文件，不会清理已提交内容。保留许可证和必要的作者归属；删除归属不能替代隐私审查。

## Git 与托管平台记录

检查所有分支、标签、提交内容和提交消息，以及 PR／issue 正文、评论、修改记录、附件、Actions 日志与 artifact（含基准观察和诊断记录）、Release 和仓库描述。

**新提交替换文件，不会删除旧版本；编辑 PR 正文也不等于删除旧差异或所有历史记录。** 不应仅因主分支内容已整理，就认定整个仓库可以安全公开。

需要彻底排除旧记录时，先确定保留历史还是从经过审查的快照建立独立公开仓库。历史重写会影响提交标识和协作者工作流，须单独确认、备份并验证；不要未经确认强推或删除引用。GitHub 的 PR 引用和缓存可能还需额外处理，参见 [GitHub — Removing sensitive data from a repository](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。发现真实凭据时应先撤销或轮换，不依赖删除文本解决风险。

## 发布前确认

最后复查将要公开的具体文件树和平台记录，确认示例可运行、能力描述与[验证范围](validation.md)一致，再由仓库管理员决定可见性。版本包的构建与公开流程见[版本发布](releasing.md)。不要在公开的审查报告中复制被移除的信息。
