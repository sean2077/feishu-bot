# 测试与部署验收

## 自动化检查

本地目录、配置继承和 YOLO 的回归包含 `local-config`、`local-runtime`、`session-launch-identity` 及 `native-local-inherit`；原生测试使用真实 CC 和本地模拟模型验证用户／项目配置、技能、插件、MCP、问答及停止恢复，不替代真实模型验收。`native-origin`、`native-result-origin` 和 `native-skill-origin` 覆盖混合 UUID、后台归属与连续多轮交付。`feishu-card-stream` 使用真实 SQLite 和模拟网络验证单消息、多区域更新、平台元素 ID 规则、持久序列、失败不重建与关闭后的迟到响应；真实 CardKit、客户端外观及平台自动结束流式的长任务边界另行验证。

```sh
npm run check
```

检查包括类型检查、单元与交互回放、构建和原生运行时测试。平台 CI 配置覆盖 Ubuntu／Windows 与 Node.js 22.16／24；工作流定义本身不代表作业已经成功，应查看对应提交的实际结果。

`stop-rate-limit.test.ts` 使用实际 Gateway／SQLite 与模拟 Worker 验证：普通任务达到每分钟限额后，群维护者和获准私聊用户仍能停止已有运行；普通输入继续受限、非维护者不能停止共享会话，停止不轮换 session 或启动第二个 Worker。该用例不代表真实飞书或进程清理验收。

`conversation-contract.test.ts` 验证授权群＋授权作者＋明确 @、未授权静默、默认零背景、按需历史过滤与分页归属、同群跨线程续接、停止保留会话、压缩控制边界、重启恢复、表情竞态和同卡去重。原有审批、工作区、受控操作、outbox、文件快照及资源回收测试继续运行。

`native-runtime.test.mjs` 使用实际 Agent SDK／CC 及生产 launcher，模型响应由本地确定性服务提供，检查权限往返、忙时补充、多输入归属、热续轮、中文与空格路径、附件和原生工具。

`native-contract.test.mjs` 进一步验证原生 `/compact` 的实际压缩与历史不足分支、压缩后的同 session 续接、真实进程重启恢复、无效 session 不静默新建、历史 MCP 往返、流式思考／答案归属。端到端用例运行生产 Gateway、SQLite 和实际 CC，飞书传输与推理响应使用测试替身；它不是实际飞书平台验收。

配置与文档测试检查通用示例、显式凭据配置、时区继承、本地文档链接和忽略规则。所有测试数据应是虚构资料，不需要真实服务密钥。

模拟响应不能证明真实模型的理解质量、子代理规划或性能。Linux 结果不能替代 Windows 验证；平台 CI 也不能替代某个实际部署的网络与工具链验收。

新增首次启动回归覆盖未填模板、无聊天绑定、CLI 参数缺失、配置语法错误脱敏、目录诊断聚合、SQLite 探针清理和模型探针响应格式。长回复回归覆盖文件失败、重启补发、已确认文件不重送、停止与撤权竞态及旧数据库迁移。`outbox-shutdown.test.ts` 进一步使用真实 Gateway／SQLite 与被控制为无限等待的模拟飞书卡片或文件调用，覆盖最终卡片创建、必要完整文件上传、已知卡片更新三种关闭边界：本地退出不等待远端，不伪造已交付、不重复未知外部写，已知 ID 可安全恢复更新，迟到结果不触碰已关闭的数据库。这不是实际飞书网络行为验收。

`approval-late-card.test.ts` 用实际 Gateway／SQLite 和延迟返回的模拟飞书创建请求，检查服务关闭并释放 SQLite 后、以及 `/stop` 已取消请求后才返回的审批卡。已失效请求不能重新索引成有效输出或获批；卡片只尽力更新为已结束，不等待网络，也不承诺真实飞书的外观更新一定成功。

`process-tree.test.ts` 创建真实的父、子、孙三代进程，检查 PID 存活状态及心跳停止，而非仅断言调用过 stop。此用例在 Windows 也运行；测试结果不能外推为任意脱离父进程的系统任务都可回收。工作区路径测试使用实际目录别名，核对规范路径、已有文件及会话身份保持不变。

Windows 的已退出根进程测试同时记录 `windows-cim-cleanup-stages` 诊断行：PowerShell 内部的 started、snapshot、ancestry 和 termination 阶段累计耗时，以及 Node 侧包含进程启动和退出的总耗时。测试继续验证真实子孙 PID 和心跳；计时不会替代清理确认。生产路径默认不打印进程 ID、命令行或完整 WMI 快照；仅在 CIM 清理失败时错误包含最后完成的阶段与总耗时。该证据可以分别估算 CIM 查询、树关系计算及目标进程终止；Node 总耗时减去 PowerShell 内部耗时还包含进程启动、退出、IPC 等开销，无法单独归因为启动。单次 CI 测量不能推断总体失败率，已消失的中间祖先仍无法安全重建。

## 迁移交互专项

四项功能分别由以下测试文件审查，生产改动没有另建任务规划器：

| 功能 | 测试与关键验收 |
|---|---|
| `/btw`、`/ps` | `supplement.test.ts`：无前台不启动、鉴权、字面 slash 正文、来源与附件、compact 边界、审批可操作、轮次结束／停止／新建／退出／重启竞争、限速与容量。 |
| 原始消息 | `feishu-raw.test.ts`：虚构原始 text/post/image/file 通过锁定真实 SDK 和生产适配器；富文本图片／附件、locale、引用、线程、缺失内容拒绝，以及未经授权的合并转发零预读。 |
| 多图合批 | `image-batch.test.ts`：关闭兼容、固定窗口、数量上限、作者／聊天／线程／引用边界、原消息 UUID、去重、审批、compact、单文件／总量／下载失败、撤权、停止、新建及重启。重启中的未到期窗口使用局部冻结的逻辑时钟，恢复后以第三张图片达到数量上限来验收持久来源与会话；真实计时到期另有独立回归。 |
| `/usage` | `usage-report.test.ts`：字段缺失与非法值为未知、原生结果 ID 去重、重开数据库、旧库覆盖不完整、当前会话范围、无额外模型与 Worker。 |

定向执行不替代完整回归：

```sh
node --experimental-strip-types --test --test-concurrency=1 tests/supplement.test.ts tests/feishu-raw.test.ts tests/image-batch.test.ts tests/usage-report.test.ts
npm run build
node --test tests/native-migration.test.mjs
npm run check
```

`native-migration.test.mjs` 直接运行锁定的真实 CC／SDK、Gateway、SQLite、Worker 和生产 `bindFeishuInbound`。测试在真实 Channel SDK 分发器注入虚构原始事件；只有 WebSocket 网络入口、飞书传输和模型响应内容为替身。不能把这类测试写成真实飞书线上验收。分发器返回仅表示已入队，测试等待实际 Gateway 处理结束，不通过关闭 SDK 队列、放宽超时或降低断言规避异步边界。

贯穿旅程包括：初始任务 → 两位作者的 `/btw /new` 与 `/ps /compact` 字面补充 → 实际原生工具请求 → 未授权成员不能批准、维护者批准、重复回调只执行一次 → compact 排队且后续补充不越过 → 同卡思考／答案与必要完整文件确认后，各原消息才 Done → `/stop` 后原 session 续接 → 两张待合批图片持久保存后重开 Gateway／SQLite → 同一原生 session 的真实 Read 工具读到两份文件。检查实际模型请求、工具结果、消息 UUID 集合、卡片 ID、文件字节、session ID 和本地副作用标记次数。

另一项真实原生测试用不同的合成 token 声明连续执行两轮，再重启续接一轮；逐轮检查 SDK result UUID、主循环响应模型和 `result.usage`，确认没有累加 `modelUsage` 的累计快照。带工具旅程同时验证同轮多次模型调用的汇总。它证明锁定版本的采集与去重口径，不证明真实账单、视觉理解或子代理用量完整性。

## 实际接入清单

### 本地目录与原生配置迁移

`local-config.test.ts` 覆盖默认隔离与 `acceptEdits` 兼容、直接目录和自选 CLI 相对路径解析、继承配置不强制直接目录、互斥配置及非法值。`local-doctor.test.ts` 使用临时目录检查工作目录、继承配置来源与可执行文件，拒绝不存在或仅能报告 Node 版本的程序，且不在诊断中展示私人路径；可执行版本成功分支的脚本替身仅在非 Windows 平台运行。所有这些检查都不调用外部服务，不证明用户配置已被实际加载。

真实接入时先保留旧配置、自动启动入口和状态备份，在获准测试聊天使用不会触发真实外部写入的目录。分别验证默认隔离配置，以及显式 `cwd`、`nativeConfig: inherit` 的组合：由实际工具读写测试文件确认 cwd；通过无副作用的测试 hook、测试技能和测试 MCP 确认原生加载；插件只验证实际需要的能力。对自选 CLI 记录版本及与锁定 SDK 的兼容结果，不以 `--version` 通过代替原生交互验收。

显式 YOLO 模式需验证常规工具不会产生多余权限卡、显式 deny／ask 仍按原生规则处理、追问仍可完成；受控外部操作与网关独立确认另行验证。测试新会话、停止、回收、重启、compact 后原 session 与历史位置一致；修改 cwd／配置身份时旧会话不能静默切换，明确 `/new` 后才使用新身份。共享原生历史目录不能让一个聊天恢复另一个聊天的会话，旧桥接服务的映射不会自动导入。

Windows 还应验证实际常驻账户、任务计划程序环境和无窗口启动；切换同一应用前确认旧入口停用。完成后分别记录本地自动化、模拟模型、Windows 实机、真实飞书和真实模型的证据，未执行项标为未验收。

| 范围 | 验证内容 |
|---|---|
| 飞书 | 授权／未授权用户与群、明确 @、不带 @ 的引用、私聊、附件及卡片回调 |
| 群历史 | 权限不足明确报错；仅当前群、获准作者；分页、引用、附件不绕过范围 |
| 展示 | 临时表情清理、完成表情、引用原消息、思考与答案同卡、工具轨迹隐藏 |
| 模型服务 | 真实 Messages 流、忙时补充、子代理、所需多模态能力、原生自动与手动压缩 |
| 会话 | 两群两私聊并行；跨线程不分裂；重启与空闲回收后按原 ID 续接；只有 `/new` 新建 |
| 权限 | 无权、过期、重复或转发卡片不能批准；等待审批时仍能接收普通输入 |
| 外部操作 | 仅访问获准测试资源；写操作审批；结果未知时不自动重做 |
| 运行环境 | Linux／Windows 工具链、时区、代理、CA、路径与进程退出 |
| 故障恢复 | 断网、重投、进程中止、慢卡片／表情请求；无误报完成、静默重置或盲目重复写入 |

`doctor --probe-feishu` 只验证应用身份，`doctor --probe` 只有基础模型请求检查；都不能替代完整清单。没有实际执行的项目不能标为已验收。升级后的默认值和会话保留规则见[会话行为契约](conversation-contract.md)。

### 手机与桌面人工旅程

仅在独立测试应用、测试群及获准私聊执行，部署和真实凭据配置另行授权。准备两名普通获准成员、一名维护者和一名未授权成员；凭据只在主机配置，不发送到聊天。涉及工具写入仅使用可安全核查的本地测试文件或独立测试资源，不用真实生产写操作制造故障。记录操作系统、Node／SDK／应用版本、客户端版本、配置、时间、结果和未验收项，不保存完整原始事件或凭据。

1. **入口与格式。**桌面和手机分别发送明确 @ 的文本、带文字与图片／文件的富文本、独立图片、文件和引用。检查正文、文件名、引用原消息及线程位置。未授权成员、无 @ 群消息、只引用机器人不触发；合并转发明确提示不自动展开。损坏资源使用测试注入验证，不要求客户端伪造 API 事件。
2. **补充与审批。**开始一项足够持续的测试任务，另一位获准作者发送 `/btw`，原作者发送 `/ps`。正文中的 `/new` 或 `/compact` 不执行管理命令。核对同一会话和原任务答案卡、作者区别、原消息回执；空参数及空闲状态提示准确且不调用模型。等待审批时加入 compact 与后续补充，分别在手机和桌面尝试普通成员批准、维护者批准／拒绝以及重复点击；不得执行两次或越过 compact 边界。目标先结束，未交付补充明确取消。 对追问卡片另测两种**已在锁定 SDK 模拟入口复现**的重复点击：先空提交、补齐全部选项后再次提交；同一多选项连点以取消。每次操作应刷新同一卡片的按钮版本，补齐后可再次提交，同一选项可切换；记录手机／桌面实际结果。另测旧缓存按钮或刷新失败时，使用原聊天获准作者的 `/answer`（多题为完整问题键的 JSON）恢复，不用未经授权的原始事件回调绕过 SDK。
3. **完整交付。**让测试任务产生超长答案或必要附件，检查同卡可展示思考和答案，签名及工具轨迹不出现。文件尚未确认送达时没有 Done。控制测试环境网络产生上传未知结果后，先核对远端，再决定是否由维护者明确补发；不得为了验收盲目重复未知写入。
4. **图片边界。**先保持 `imageBatchMs: 0` 确认独立行为，再在主机配置如 800 ms、8 张及 40 MiB 总量。同一作者、引用／线程内连续发送两张独立图片，每条都须平台实际携带 @；手机不能独立 @ 的图片不得由此前文本的 @ 代替。再交替作者／线程，插入文本、命令或 compact，检查不跨边界合并。发送数量上限及大小上限样本，核对整批失败不是部分执行；等待期间审批仍可操作。富文本配图不与邻近图片合批。
5. **停止与重启。**图片窗口内分别测试 `/stop`、`/new`、服务正常重启，以及受控异常退出；旧批次不进新会话。从未发送的普通图片可在原会话恢复，旧运行补充不能变成新任务；已发送但结果未知的输入不自动执行。比较停止／续接／重启前后的原生 session ID，只有 `/new` 改变。不要仅依赖模型口头表示“记得”。
6. **用量。**在尚无会话、运行中、结果后、compact 后、重启后和切换本聊天历史后查询 `/usage` 与 JSON，比较 SDK 实际结果字段及累计，不额外产生模型请求。缺失字段为 null，旧会话显示历史不完整；不把输出补发计成新一轮或把 token 累计当作当前上下文。检查另一聊天的数据不可见。

手机和桌面分别记录，不用某一端通过代替另一端。网络恢复、真实模型多模态／子代理及长时间运行的验收结果应单独列出；未配置真实环境时保持“未验证”。

原生后台与定时验收先记录已有任务，仅创建带独立测试标记的本轮任务并只清理其返回 ID。核对实际触发、取消、原生输入消费确认和输出归属，不能用模型口头回复代替工具结果。后台来源按原生 run 标识分开；未知后台不能借用下一条前台回复，原生明确确认消费的前台输入仍须完成。后台轮次折入后续消息时，已发卡片保留真实平台引用并说明合并，旧预览必须结束；回归模拟与真实原生进程、真实飞书触发分别记录。

## 性能测量

`worker_ready.startupMs` 记录进程初始化时间，原生 fixture 另记录首轮和热续轮时间。它们不等同于真实模型或飞书首字延迟，也不是与其他产品的性能比较。

比较性能时固定模型、工具、权限、输入和运行环境，区分首次启动、进程复用、模型生成与工具执行。不要用未测量的加速倍数替代这些数据。
