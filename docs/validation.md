# 测试与部署验收

## 自动化检查

```sh
npm run check
```

检查包括类型检查、单元与交互回放、构建和原生运行时测试。平台 CI 配置覆盖 Ubuntu／Windows 与 Node.js 22.16／24；工作流定义本身不代表作业已经成功，应查看对应提交的实际结果。

回归场景涵盖消息与会话归属、群背景、权限卡片、附件、outbox、停止、资源回收和原生进程复用。`native-runtime.test.mjs` 使用实际 Agent SDK／CC 及生产 launcher，模型响应由本地确定性服务提供。

原生测试检查权限往返、忙时补充、多输入结果归属、热续轮、中文与空格路径、附件读取及原生工具。配置与文档测试补充检查通用示例、显式凭据配置、时区继承及本地文档链接。

模拟响应不能证明真实模型的理解质量、子代理规划或性能。Linux 结果不能替代 Windows 验证；平台 CI 也不能替代某个实际部署的网络与工具链验收。

## 实际接入清单

| 范围 | 验证内容 |
|---|---|
| 飞书 | 独立测试应用；群聊／私聊、@、引用、附件、卡片和重复事件 |
| 模型服务 | 真实 Messages 流、工具调用、忙时补充、子代理、长上下文及所需多模态能力 |
| 权限 | 维护者和普通用户；无权、过期、重复或转发卡片不能错误批准操作 |
| 会话 | 两个群及两个私聊并行；恢复不访问其他聊天历史；后台结果回到正确位置 |
| 外部操作 | 仅访问获准测试资源；写操作审批；结果未知时不自动重做 |
| 运行环境 | Linux／Windows 工具链、时区、代理、CA、路径与进程退出 |
| 故障恢复 | 断网、重连、进程中止、消息重投；无静默丢失或盲目重复写入 |

`doctor --probe` 只有基础连接检查，不能替代完整清单。没有实际执行的项目不能标为已验收。

## 性能测量

`worker_ready.startupMs` 记录进程初始化时间，原生 fixture 另记录首轮和热续轮时间。它们不等同于真实模型或飞书首字延迟，也不是与其他产品的性能比较。

比较性能时固定模型、工具、权限、输入和运行环境，区分首次启动、进程复用、模型生成与工具执行。不要用未测量的加速倍数替代这些数据。
