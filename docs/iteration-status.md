## 产品目标

先在飞书＋原生 Claude Code 的既定场景做到比 cc-connect 更自然、可靠、易维护，而不是复制全部渠道和执行底座。对标以相同任务的实际体验为准：首次部署需要的人工步骤、多人补充是否完整进入会话、追问与附件是否好用、故障后是否知道如何继续、恢复是否避免重复副作用，以及同条件的延迟和资源占用。测试通过只证明所覆盖的契约；没有真实客户侧验收或同条件对照，不宣称已经整体超越。

## 已有保障

授权群＋授权作者＋明确 @；私聊独立授权。默认零背景，历史／引用／附件限定当前聊天与作者。同群连续会话；停止、回收、重启和原生压缩保留 session。输入与最终回复事务持久化，未知外部写不自动重放；已有远端 ID 安全恢复。卡片与必要文件全部确认交付后才 Done。进程停止未确认时保留名额和数据锁。多人追问选项按操作人隔离。

这些已有行为与修复细节见历史记录和[对话契约](conversation-contract.md)，不得重复开发或弱化断言。

- 真实飞书身份、长连接、事件、手机／桌面卡片、文件上传、断网与重启补发；所选模型的流式工具／后台能力。凭据仅在独立运行主机配置。
- 表情远端结果长期不可见的悬置、人工补发可能重复的已知边界；没有端到端 exactly-once 保证。
- 可比较的真实延迟、闲置资源、token 与失败率；本批确定性 fixture 基线不能替代这些数据，没有实测前后对照不宣称性能提升。
