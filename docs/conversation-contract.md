# 对话行为

本页是用户可见对话行为的当前契约：授权、会话、输入、审批、compact、交付和用量。模块边界与进程模型见[架构](architecture.md)，配置项见[部署与配置](deployment.md)，操作示例见[使用场景](usage.md)，术语见[术语](terminology.md)。

## 授权与触发

群聊输入默认须同时满足三个条件：群被显式 `groups[]` 绑定或由 `chatId: "*"` 的兜底绑定覆盖；作者在该群 `members` 中（`allowAllMembers: true` 时任意用户）或是对应项目的 `maintainers`；消息明确 @ 本机器人。私聊须在 `dms` 中授权，不需要 @。

- 显式群绑定优先于兜底绑定。`chatId: "*"` 是唯一允许的兜底绑定，只覆盖未显式绑定的群，不改变已绑定群的作者策略，也不作用于私聊。
- 省略 `members` 或配置为 `[]` 时仅项目维护者可用；不接受通配符成员。`allowAllMembers: true` 显式放开该群所有用户。
- `mentionOptional: true` 只免除该群的 @ 要求，群和作者授权照常生效；默认 `false`，修改后需重启。
- 不按显示名授权，不把 @全体、正文中的名字或仅回复机器人当作明确 @。

未授权群和用户的消息在业务处理入口静默丢弃：不产生回执、回复或正文记录，也不展开引用或下载附件。同一权限判断用于恢复后的待交付输入、历史、引用、附件和卡片回调，避免从其他路径读回被拒绝的信息。

已获准聊天中没有管理权限的成员执行 `/compact` 等管理操作时，可收到说明；这与向未授权用户回复“无权限”不同。审批点击来自平台回调，不需要再发一条 @ 消息。

## 默认不注入群背景

`limits.backgroundMessages` 默认 **0**：获准用户的非 @ 群消息不进入本地背景缓存，也不会作为下一条提问的隐藏前缀。只接收明确请求，避免无关讨论占用上下文或被当作新的任务指令。`mentionOptional: true` 的群中，获准作者的每条消息都是前台触发，不进入背景缓存。

这对应关闭 `group_chat_history_share` 的行为，本项目不增加第二个同义开关。非零 `backgroundMessages` 是显式选择的有界缓存，部署者应自行配置条数、时间并告知参与者；授权过滤始终生效。

需要前文时，Agent 使用 `read_chat_history`：

- 默认一页 20 条，最大 50 条，总正文有长度上限；不做自动全量翻页、RAG、定时同步或额外模型总结。
- 参数不接受 `chatId`，聊天范围来自当前会话。分页游标绑定房间、会话和 15 分钟有效期，服务重启后失效。
- 整群范围的会话可以单独查询已在本聊天观察到的线程（不支持时间范围），但不会因此创建另一条会话；话题会话只读当前话题。
- 只返回当前获准作者及本机器人的消息。授权作者的非 @ 发言可在显式调用时作为资料读取；未授权作者不会因查询历史进入上下文。引用展开遵循同一规则；合并转发不自动递归展开；附件只先返回描述，需要时单独下载。

按需读取需要飞书应用的相应消息权限（见[部署与配置](deployment.md)）。没有权限不是“历史为空”，接口失败会明确返回工具错误。

## 连续会话与进程生命周期

默认每个群一条当前会话，群内所有获准发言者与线程共同推进；每个私聊独立。此时线程只影响引用和回复位置，不改变房间键。

会话与进程分开管理。服务重启、空闲回收或 `/stop` 后，下一条消息用保存的原生 session ID 明确恢复，不猜测“最近一条会话”，也不通过重新拼接全部历史代替恢复。

| 操作 | 结果 |
|---|---|
| 普通输入、同群不同线程（整群范围） | 继续当前会话 |
| 话题范围群：顶层触发／话题内触发 | 开启新话题会话／继续该话题会话 |
| 空闲回收、服务重启 | 重新启动进程，续接相同原生会话 |
| `/stop` | 取消当前会话的执行、待交付输入与审批；保持会话 |
| `/btw 正文`、`/ps 正文` | 仅补充当前前台运行；无目标不另起任务 |
| `/compact [保留重点]` | 在当前会话中运行原生压缩 |
| `/new` | 明确建立新会话，旧会话保留 |
| `/resume <名称或ID>`、`/rename <名称>` | 名称和唯一短 ID 只在当前聊天解析；恢复不自动启动模型 |
| `/model [配置名]`、`/profile [配置名]` | 查看或选择管理员预定义的模型／effort，在安全轮次边界生效 |
| `/artifacts [文件ID]` | 查看或重新发送已完成的冻结文件，不重做原任务 |
| `/usage [--json]` | 只读查询选中会话已报告用量，不唤醒进程 |

### 话题会话

群配置 `sessionScope: "thread"` 时，该群按飞书话题划分会话，适合多人同时处理不同问题的群。触发条件和授权不变。

- **开启与续接。** 群主时间线上的一条新触发消息（默认需要 @）开启新话题：首个回复以话题形式回复该消息，形成独立房间和原生会话。普通引用回复同样是顶层消息，开启自己的话题，被引用内容照常作为引用。话题内的触发消息续接该话题会话，任何获准作者都可以参与；话题内不 @ 的消息不触发，`backgroundMessages` 只缓存话题内的消息。顶层不触发的消息不创建房间。
- **归属。** 只有带飞书 `thread_id` 的消息归入已有话题，`root_id` 只用于定位该话题的根消息；不依赖内存登记，重启或首个回复尚未完成时到达的追问仍进入同一会话。
- **回复位置。** 回复、状态卡、通知和文件都发在话题内。飞书拒绝话题回复（230071、230072）时报告配置不符，不改为普通回复，也不退回整群会话；该输入不会标记 Done。
- **历史。** `read_chat_history` 只读当前话题，拒绝整群和其他话题；需要别处内容时请引用回复。飞书话题容器不支持时间范围，翻页使用游标。
- **管理命令。** `/new`、`/stop`、`/compact`、`/resume`、`/sessions` 等只作用于所在话题；在群主时间线发送时只返回提示，不猜测“最近的话题”。新的顶层触发就是开启新会话的明确操作，旧话题会话保留，在原话题里继续 @ 即可续接。
- **根消息背景。** 在既有人工话题里，尚未交付给当前会话的[话题根消息](terminology.md)若可读，会作为引用随输入提供。读取临时失败时本条请求照常继续，后续输入再次尝试；根消息已成功读取但不存在或作者不可读时，本进程内该会话不再重复查询。成功读取、收到其他输入或执行 `/compact` 都不代表根消息已经送达；只有原生确认消费携带根消息的输入或返回其结果后，交付事实才按会话持久保存，停止、重启和压缩后不重复注入，`/new` 的新会话独立记录。尚在同一进程输入流中的根消息不重复排入，未确认的中断则允许再次提供。
- **卡片补充。** 卡片快捷补充绑定其所在话题、会话和当前轮次，不依赖消息里的话题字段；交付前仍重新校验房间与作者授权。
- **共享工作区与附件。** 同一群的话题共用工作区、原生 HOME、项目 `CLAUDE.md` 与原生自动记忆，并发话题可能同时修改同一批文件；需要并行改代码的群请使用不同的项目目录或 worktree。入站附件按话题分开保存，一个话题的文件工具（Read／Grep／Glob）和 `send_file` 不能使用另一个话题的上传；切回整群范围后，整群会话同样不能使用各话题的上传。由于原生 HOME 共享，模型仍可用文件工具读取同群其他话题的原生会话记录：话题隔离的是默认对话上下文，不是同一群内的访问边界，群与作者授权仍是边界。
- **群级限制。** 拆分话题不放宽群级限制：`messagesPerMinute` 按“群＋作者”计算，`inboxPerRoom` 统计全群所有话题的待交付输入；多个话题的消息与卡片补充同时到达时共同预留这一个额度，不会因并发突破上限。每个活跃话题占用一个原生进程，同群各话题共用 `maxWorkersPerChat` 额度（见[容量与回收](architecture.md#容量与回收)）。
- **旧附件目录迁移。** 旧 `inbound/topics` 目录升级到独立话题附件目录时，迁移失败会阻止该群工作区准备并报告原因；同名但内容不同的文件保留两份，不覆盖或删除。整群会话始终拒绝把旧话题子目录当作自己的上传。修正磁盘、权限或冲突条目后再次触发即可继续迁移。
- **当前限制。** `/resume` 只解析本话题房间的会话，不支持跨话题接管。切换 `sessionScope` 后需重启；另一范围的会话和原生历史保留，切回后可继续，旧的整群历史不会拆分或复制到话题。切换时旧范围中尚未交付的排队输入会在恢复校验中取消，请在切换前处理完。

### 恢复与原生身份

恢复失败或返回不同 session ID 时保留原映射并报错，不静默新建。历史文件损坏、被删除或尚未持久化的信息不能凭空恢复；结果未知的外部写也不会自动重放。

新会话的原生 ID 未能保存或与已记录值冲突时，网关停止该运行并提示，之后不会以空 ID 启动替代上下文，服务重启也不解除；维护者用 `/resume` 选择已记录的会话或用 `/new` 明确新建。只有可以证明从未交接输入的启动才自动允许重试。机制见[原生进程生命周期](architecture.md#原生进程生命周期)。

只回收已确认空闲的进程；后台任务、Monitor、原生会话定时工作、审批、交付中的最终回复及状态未知的工作不回收。恢复历史不会复活已经死亡的监控或撤销外部操作。原生进程额度或内存准入阈值已满时，输入保存并提示一次等待原因，名额释放后自动处理，已有工作不会被取消。

### 停止

`/stop` 在取消任何内容前先保存[停止暂停](terminology.md)。之后取消执行、待交付输入、审批和回执；若取消待交付内容的状态无法保存，原生进程仍会停止并释放名额，但本房间保持暂停，服务重启也不解除。暂停期间的获准输入被暂存，并告知它们会随下一次成功的 `/stop` 一并取消；该次停止成功后会提示暂存输入已取消，请届时重新发送。回复卡上的“停止”按钮遵循同一规则。

原生意外退出时，已发送但无结果的输入标为 uncertain 并释放队列占用，不重放；保存该状态失败时由定期扫描在存储恢复后补做。

### 会话名称与目录

新会话启动时，原生会话在 Claude Code 会话列表中的显示名取自首条获准人类消息：群聊包含作者显示名，折叠为单行并截短，不额外调用模型。自动标题持久保存在本聊天会话记录中；此前建立的会话在下一次启动时补设。`/rename 名称` 先保存名称和同步修订，再异步请求更新原生显示名；`/rename -` 清除聊天内名称并恢复保存的自动标题。显示名不改变原生 session ID、transcript、输入排队、压缩或恢复行为。

原生标题同步区分目标、最后一次确认值与[修订](terminology.md)。控制请求经过有界单 writer，先等待原生初始化（受原生进程自身 30 秒启动上限约束），再以 5 秒截止涵盖等待写入、管道阻塞和 ACK，冷启动较慢不会使标题直接记为未发出；响应必须匹配 request ID。未发出、明确拒绝、结果未确认分别记录，迟到或旧修订响应不能把新标题标成已确认。标题同步失败不停止健康的原生任务，不阻塞首条输入；同一未确认请求不自动重放。

会话目录只搜索本聊天的名称、原生标题与 ID，按新接收的人类输入排序，并使用签名键集分页。人工名称与 `/resume` 的确定性解析规则不变；自动标题只是可重名的检索元数据。命令与翻页见[状态与恢复](usage.md#状态与恢复)。

### 本地终端交接

本地 `session run` 是显式离线交接：服务先停止，命令持有同一个 `gateway.lock`，验证历史会话的 cwd／配置身份／已应用模型配置并使用明确的原生 ID 恢复。存在未确认输入、交付、审批或固定操作时拒绝交接；原生进程树退出未确认时保留锁。终端中的输出和工具审批留在本地，网关用量覆盖标记出现缺口。重启服务后继续选中的同一会话，步骤见[部署与配置](deployment.md#本地终端交接)。

## 运行中补充

`/btw` 与 `/ps` 是网关别名，不是原生同名 slash，也不是独立旁路问答。正文进入已有原生输入流，绑定接收时正在执行的前台输入；没有未完成的前台输入时拒绝，空闲热进程、仅有后台活动或正在 compact 都不能充当目标。普通忙时输入的行为不变。

补充正文中的 `/new`、`/compact` 等按文字处理；补充不能回答审批或扩大工具权限，仍使用原有授权、去重、容量、速率、持久化和输出归属。已排队的 compact 是边界，补充不能越过。目标结束、Worker 退出、`/stop`、`/new` 或切换会话时，尚未发送的补充取消并发送系统通知，不转成新任务；已发送且结果未知的补充不自动重放。回执、宿主交接和恢复细节见[运行中补充](supplements.md)。

## 消息完整性与附件

Go 入站适配层检查已知格式是否完整。缺失资源、损坏 JSON、未支持的富文本元素及超出主输入限制的消息在授权之后明确拒绝，不把部分文字当完整请求。完整原始对象仅用于内存检查，不保存到模型输入、数据库或日志；合并转发不预读，合法引用另经范围检查。支持格式见[原始消息格式](raw-messages.md)。

`limits.imageBatchMs` 默认为 0。开启后，同聊天、同作者、同会话且引用／线程一致的连续独立图片在固定窗口内合成一次原生输入，每条消息仍独立通过授权和触发；任一下载失败或超限时整批取消，不执行部分输入。规则见[连续图片输入](image-batches.md)。

附件在派发时下载，先完整写入私有临时文件，校验通过后才发布到会话的附件目录（见[架构](architecture.md#上下文与文件)）。准备失败（例如下载失败或超限）发生在交给原生之前时，该输入取消并明确提示未提交给模型，处理后重新发送即可，同一附件可再次下载；已发布的文件可能保留复用，不代表所在批次已提交给模型。

## 压缩

网关不实现自动压缩策略，不用 token 估算再调用模型总结。Claude Code 自带的原生自动压缩照常工作，网关只显示其状态。

`/compact` 是经过授权的原生命令，不放入普通 JSON 提示词。忙时把它作为持久控制边界，等当前工作轮次、最终交付与必要交互结束后执行；其后的普通输入暂缓交付，审批回调不受阻塞。执行前有可见状态，执行后保持同一个 session。

只有收到原生 `compact_boundary` 才显示实际完成压缩；原生返回成功但没有边界时显示无需压缩，例如历史不足。失败不切换新会话。

## 回执

接受的输入添加临时 `OnIt`，表示已接收或正在处理，不表示已经成功。结果成功且最终回复确实送达后，移除临时表情、添加 `Done`。失败、取消、停止和交付不明确时只清理临时表情；重启也会清理遗留的处理中标记。

- 表情更新按消息串行维护目标状态，完成不会被晚到的“处理中”覆盖。只删除本应用的表情，不删除其他机器人或用户的表情。表情 API 故障不阻塞原生任务，重试不会重做任务。
- 已确认创建的表情在清除后发生响应丢失或重启时，完整查询确认本应用表情已不存在即可完成清理，再添加 Done。创建结果未知时只查询核对、不重复创建，一小时后仍未观察到则停止核对。明确失败的创建按普通创建重试；明确拒绝的 OnIt 不会覆盖随后的完成或取消目标，也不会让 Done 等待一个已知未创建的表情。
- 本轮结果合并消费多条输入时，按原生 UUID 分别完成这些消息的回执，不假设一条输入对应一个结果。多图批次映射回每张原消息；补充不另外生成答案卡。后台输出只使用可靠的任务来源关联，未知来源不挂到最新发言上。“已启动监控”的完成标记仅表示本轮回复完成，不表示监控任务已结束。

## 回复卡与交付

一个回复周期共用一张[回复卡](terminology.md)，引用本轮最初触发消息，不随最新补充者漂移。思考与答案分区，思考默认折叠、可展开，显示最近 10 段模型公开思考的开头各 180 字（更早的步数只计数），不另行生成摘要；公开内容块按原生消息／块标识去重，不展示思考签名、不可展示块和工具调用轨迹。没有思考内容时不额外生成。结束时显示用时、实际模型、已报告用量、末次模型请求的输入规模与原生上下文窗口，以及实际工作目录；缺失字段显示未知。审批与追问保留交互卡。

最终答案和合并卡片先落入 outbox，再进行网络更新：

- 更新失败重试同一消息 ID；消息创建超时且结果不明时不盲目创建第二份，可从 `/outputs` 查看并显式补发。暂时限流尊重服务端等待时间并限制自动尝试次数；月配额耗尽等永久拒绝暂停自动重试。
- 超长答案受卡片容量限制，正文另附文件；完整正文、文件目标和发送状态一起持久化。只有卡片与必要文件均确认送达，才标记 Done。
- 附件按触发来源归属到轮次：只有与回复共享来源的未完成文件才阻塞该回复；回复没有来源记录时保守按会话等待，更早轮次明确失败的附件保留在 `/outputs`，不阻塞后续回复。手动 `/artifacts` 取回产生独立交付记录，失败也不阻止后续回复标记 Done。
- 文件发送失败或结果未知时，卡片尽力显示未完整送达，`/outputs` 保留文件阶段的补发记录。重启后可从持久正文重新生成文件；补发不重新请求模型，已记录成功的文件不重复发送，状态未知的发送只接受显式补发决定。
- 消息 UUID 与请求内容冻结，CardKit 创建、文件上传和消息发送分别确认。UUID 一小时去重窗口不保证恰好一次，不据此自动重放未知写入；补发前若可能已被接受，仍需人工核实。

卡片状态：审批与追问等待暂停流式状态但不标终态，答复后继续原卡。预览曾明确失败并暂停更新时，进入等待仍尝试一次状态更新；再次明确失败则保持暂停。平台明确流过期或关闭时，仅对已有实体全量更新。紧凑回复卡顶部状态行随交付状态更新：文件待送达、未完整送达、取消或放弃时，不保留此前“已回复”或“处理中”。停止和重启保留可恢复的旧卡收尾记录；恢复已保存的旧版卡片时兼容原有布局。

**撤回输入与放弃交付。** `/cancel-input` 只接受经输入锁和派发锁共同证明尚未交接的 queued 项目；图片批次整体处理，已提交和结果未知的输入不伪称可撤回。`/discard-output`（[交付放弃](terminology.md)）沿可核实的来源关联放弃同轮依赖，原子保存放弃决定及已知卡片的收尾交付；后到的同轮原生最终回复继承来源标记，原轮结束后才完成的后台结果不继承、照常交付。已在途的交付不能与放弃并发提交，晚到预览 ACK 的卡片目标也持久保存。放弃不停止原生任务、不撤回远端消息、不设置 Done，且保留未知文件结果的证据。

审批转发只有至少一张维护者卡片被平台确认后，才提示已发送；全部失败时按未送达拒绝请求，不把排队发送当成维护者已收到。

## 会话配置与快捷操作

[模型配置](terminology.md)属于当前会话；群内只有维护者可更改，私聊本人可管理，获准成员均可查看。切换保持原生 ID，不改变端点、凭据、目录或工具权限。忙时保存选择，前台输入、审批、进行中的交付、原生后台工作及监控结束后再应用；等待期间新的普通输入暂缓，合法补充仍交给原轮次，不越过 compact，也不强制终止停止未确认的进程。若选择与冷启动并发，引发启动的首条输入（或完整图片批次）先用已启动的配置完成。已保存的配置被管理员移除时不静默换模型：保留已保存输入、停止自动重试并只提示一次，须明确选择可用配置或 `default` 后继续。

快捷操作重新验证签名、房间、作者、实际卡片消息 ID、当前会话、轮次／输出版本和期限（最后成功绑定后 24 小时）：

- 旧卡不能停止后续轮次；同一可见版本的停止、恢复和补发声明只生效一次，交付再次失败并刷新卡片后，新版本可再次明确补发。
- 补充表单无目标时不启动新任务；回答入口不能批准权限。
- 已完成文件只在本房间保留期内取回；路径或授权失效时拒绝，不启动原生进程。

卡片回调从收到事件帧起使用 2.5 秒处理截止，排队、校验、锁等待和数据库接受事务都计入同一预算。截止前尚未提交的补充、停止／恢复／补发声明和审批决定不会在稍后生效，卡片仍可重试；期限内已持久接受的决定继续完成，不因回调响应过期而丢失或撤销。

## 使用量

只展示原生 CLI 实际报告的所选会话用量。主循环 `result.usage` 的 input、output、cache read、cache creation 分开统计，不含子代理的独立用量；字段缺失为未知／null，不填零；模型来自实际响应元数据，不用配置别名猜测，多模型结果不擅自分摊。字段说明见[使用量](usage.md#使用量)。

按原生结果 ID 持久去重，重复结果、重启和输出补发不重复累计。统计起点、历史缺口和无法识别的结果显式披露，不把旧审计伪装成完整累计；没有稳定结果 ID 时不猜造去重键，进行中或中断而未返回结果的消耗也未知。累计不是上下文占用或费用；查询不调用模型、不扫描 transcript。

用量写入失败时保存[待补存用量](terminology.md)，答案照常交付；最终答案与输入完成状态的提交保证该结果已有用量记录或待补存观测，两者都无法保存时不把最终答案标记为完成。待补存期间 `pendingResults` 显示观测数、`historyIncomplete` 为 true、累计总量为 null，已保存小计仍可查看。服务恢复和定期扫描只重试本地记账，保留原观测时间，不重做原生任务或再次交付答案。

## 升级

- 配置字段的兼容与改写（如显式非零的 `backgroundMessages`、省略 `members`、已移除的容器字段）见[配置兼容](deployment.md#配置兼容)。
- 未交付的背景在恢复时按新配置移除，待投递输入重新校验作者。已经进入旧 transcript 的内容不会因关闭背景而消失，网关不擅自清空会话；需要干净上下文时显式 `/new`。
- SQLite 保持 schema 5 和既有会话命名空间，通过附加表及可缺省列保存交付日志、卡片生命周期、状态卡片、会话偏好、快捷控件绑定、原生身份未决、停止暂停、待补存用量和话题根消息交付，不删除旧表或改写 session 映射。用量记录与覆盖起点沿用原语义，旧会话此前用量未知，不回填不可靠计数。
- 首次建立原生身份未决表时，已绑定启动目录但仍无原生 ID 的旧会话会保守补记为未决：旧版本无法证明这些会话从未启动，需维护者明确选择后再继续。尚未绑定启动目录的会话照常按需启动，已有原生 ID 不变。
- 升级前备份 `dataDir`；不要并行运行两个实例操作同一状态库，也不要用删除状态目录来完成升级。升级步骤与回滚见[升级与回滚](deployment.md#升级与回滚)。
