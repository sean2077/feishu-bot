# 对话行为

## 授权与触发

群聊输入默认须同时满足三个条件：群被显式 `groups[]` 绑定或由 `chatId: "*"` 的兜底绑定覆盖、作者在该群 `members`（或 `allowAllMembers: true` 时任意用户）或对应项目 `maintainers` 中、消息明确 @ 本机器人。显式群绑定优先于兜底绑定。群配置 `mentionOptional: true` 时，该群所有获准作者的消息免除 @，但群和作者授权仍然生效；默认 `false`，修改后需重启。私聊须在 `dms` 中授权，不需要 @。不按显示名授权，不把 @全体、正文中的名字或仅回复机器人当作明确 @。

省略 `members` 或配置为 `[]` 时，仅项目维护者可在该群使用；不接受通配符开放群成员。`chatId: "*"` 是唯一允许的兜底群绑定，只覆盖未显式绑定的群，不改变已绑定群的作者策略，也不作用于私聊。`allowAllMembers: true` 显式放开该群所有用户；未设置时仍按 `members` 与 `maintainers` 判断。未授权群和用户的消息在业务处理入口静默丢弃，不产生回执、回复或正文记录，也不展开引用或下载附件。权限判断同样用于恢复后的待交付输入、历史、引用、附件和卡片回调，避免从其他路径读回被拒绝的信息。

已获准聊天但没有管理权限的成员执行 `/compact` 等管理操作时，可收到说明；这与向未授权用户回复“无权限”不同。审批点击来自平台回调，不需要再发一条 @ 消息。

## 默认不注入群背景

`limits.backgroundMessages` 默认 **0**。此时获准用户的非 @ 群消息也不进入本地背景缓存，更不会作为下一条提问的隐藏前缀。只接收明确请求，减少无关讨论占用上下文，避免把群里偶然出现的文字当作新的任务指令。`mentionOptional: true` 的群中，获准作者的每条消息都作为前台触发，不进入背景缓存；该群的新消息不再受 `backgroundMessages` 影响。

这对应关闭 `group_chat_history_share` 的行为，但本项目不增加第二个同义开关。已有的非零 `backgroundMessages` 是显式选择的有界缓存；需要该可选行为的部署可自行配置条数、时间，并告知参与者。授权过滤始终生效。

需要前文时，Agent 使用 `read_chat_history`：默认一页 20 条，最大 50 条，总正文有长度上限。不做自动全量翻页、RAG、历史定时同步或额外模型总结。参数不接受 `chatId`，聊天范围来自当前运行实例；分页游标绑定聊天、session 和有效期，重启后旧游标失效。已观察到的本群线程可以单独查询，但不会创建另一条主会话。

工具只返回当前获准作者及本机器人的消息。授权作者的非 @ 发言可以在显式工具调用时作为资料读取；未授权作者不会因为查询历史而进入上下文。引用展开遵循同一规则。合并转发消息不自动递归展开其中可能来自其他人的内容。附件只先返回描述，需要时单独下载。

按需读取仍需要飞书应用的相应消息权限，参见[部署](deployment.md)。没有权限不是“历史为空”：接口失败会明确返回工具错误。

## 连续会话与进程生命周期

每个群一条当前主会话，群内所有获准发言者与线程共同推进；每个私聊独立。线程只影响引用和回复位置，不改变会话键。

会话与进程分开管理。数据库保存聊天与原生 CC session ID 的映射，原生 HOME 中保存 transcript。服务重启、空闲回收或 `/stop` 后，下一条消息使用明确的 `resume` ID 恢复，不猜测“最近一条会话”，也不通过重新拼接全部历史代替恢复。

| 操作 | 结果 |
|---|---|
| 普通输入、同群不同线程 | 继续当前会话 |
| 空闲回收、服务重启 | 重新启动进程，续接相同原生会话 |
| `/stop` | 取消本聊天的执行、待交付输入与审批；保持会话 |
| `/btw 正文`、`/ps 正文` | 仅补充当前前台运行；无目标不另起任务 |
| `/compact [保留重点]` | 在当前会话中运行原生压缩 |
| `/new` | 明确建立新会话，旧会话保留 |
| `/resume <名称或ID>`、`/rename <名称>` | 名称和唯一短 ID 只在当前聊天解析；恢复不自动启动模型 |
| `/model [配置名]`、`/profile [配置名]` | 查看或选择管理员预定义的模型／effort，在安全轮次边界生效 |
| `/artifacts [文件ID]` | 查看或重新发送已完成的冻结文件，不重做原任务 |
| `/usage [--json]` | 只读查询选中会话已报告用量，不唤醒进程 |

只回收已确认空闲的进程。后台任务、Monitor、原生会话定时工作、审批、交付中的最终回复及状态未知的工作不回收。恢复历史不会复活已经死亡的监控或撤销外部操作。

恢复失败或返回不同 session ID 时保留原映射并报错，不静默新建。历史文件损坏、被删除或尚未来得及持久化的信息不能凭空恢复；结果未知的外部写也不会自动重放。

新会话启动时，原生会话在 Claude Code 会话列表中的显示名取自首条获准人类消息：群聊包含作者显示名，折叠为单行并截短，不额外调用模型。自动标题持久保存在本聊天会话记录中；此前建立的会话在下一次启动时补设。`/rename 名称` 先保存名称和同步修订，再异步请求更新原生显示名；`/rename -` 清除聊天内名称并恢复保存的自动标题。显示名不改变原生 session ID、transcript 内容、输入排队、压缩或恢复行为。

原生标题同步区分目标、最后一次确认值与修订。控制请求经过有界单 writer，5 秒截止涵盖等待写入、管道阻塞和 ACK；响应必须匹配 request ID。未发出、明确拒绝、结果未确认分别记录，迟到或旧修订响应不能把新标题标成已确认。标题同步失败不停止健康原生任务，不阻塞首条输入；同一未确认请求不会自动重放。

会话目录只搜索本聊天的名称、原生标题与 ID；按新接收的人类输入排序，并使用签名键集分页。人工名称与 `/resume` 的确定性解析规则不变；自动标题只是可重名的检索元数据。命令与翻页行为见[状态与恢复](usage.md#状态与恢复)。

本地 `session run` 是显式离线交接：服务先停止，命令持有同一个 `gateway.lock`，验证历史会话的 cwd／配置身份／已应用模型配置并使用明确 native ID 恢复。存在未确认输入、交付、审批或固定操作时拒绝交接；原生进程树退出未确认时保留锁。终端中的输出和工具审批留在本地，网关用量覆盖标记出现缺口。重启服务后继续选中的同一会话，操作步骤见[部署](deployment.md#本地终端交接)。

## 运行中补充

`/btw` 与 `/ps` 是网关别名，不是原生同名 slash，也不是独立旁路问答。正文使用已有原生输入流，保留作者、原消息 ID、UUID、引用、线程及附件。空参数返回用法；没有正在执行且未完成的前台输入时拒绝，空闲热进程和仅有后台活动不能充当目标。普通忙时输入的既有行为不变。

补充绑定接收时的原前台输入，不自动跟随下一任务。正文中的 `/new`、`/compact` 等按文字处理，不再解析成管理命令。补充不能回答审批或扩大工具权限，仍使用原有授权、去重、容量、速率、持久化和输出归属。

补充不能越过已排队的 compact 边界。等待时会说明已保存，审批回调照常处理；交给原生后发送补充回执（卡片表单含提交者与完整正文，引用格式；`/btw` 只标注提交者），不宣称模型已读取、理解或执行。目标结束或 Worker 退出时，尚未发送的补充取消并保留系统恢复通知；服务重启不会把旧补充当作新任务。`/stop`、`/new` 和切换会话取消旧运行的待交付补充。已经发送且结果未知的输入不自动重放。详情见[补充说明](supplements.md)。

## 消息完整性与图片批次

Go 入站适配层检查已知格式是否完整。缺失资源、损坏 JSON、未支持的富文本元素及超出主输入限制的消息明确拒绝，不把部分文字当完整请求。提示也位于授权之后。完整原始对象仅用于内存检查，不保存到模型输入、数据库或日志；合并转发的预先读取被阻止，合法引用仍通过独立的范围检查。[支持格式](raw-messages.md)

`limits.imageBatchMs` 默认为 0。开启后的固定窗口从第一张图开始，不随新图延长；数量和字节均有上限。只有同聊天、同作者、同会话且引用／线程一致的连续独立图片可合并，每条消息独立通过授权和触发。富文本、文本及管理命令封闭批次；compact 保持前后顺序。审批回调不等窗口。只读管理命令可以封闭窗口但不主动派发任务，既有截止时间仍负责唤醒。

每张图片的来源、UUID 和窗口先持久保存，原生发送前将整批原消息一起标记 sent。发送前下载失败或超限则取消整批并清理临时准备文件，不执行部分输入。撤权时丢弃未发送内容；`/stop`、`/new` 取消待交付批次，新会话不继承。重启或已确认清理的 Worker 退出可在原会话续接从未发送的图片；已发送但无结果的整批输入恢复为 uncertain，不自动重放。停止未确认时仍保留进程名额。配置见[连续图片](image-batches.md)。

## 压缩

不实现网关自动压缩策略，不使用 token 估算再调用模型总结。CC 自带的原生自动压缩继续工作，网关只显示其状态。

`/compact` 是经过授权的原生命令，不放入普通 JSON 提示词里。忙时把它作为持久控制边界，等当前工作轮次、最终交付与必要交互结束后执行；其后的普通输入暂缓交付，审批回调不受阻塞。执行前有可见状态，执行后保持同一个 session。

只有收到原生 `compact_boundary` 才显示实际完成压缩；原生返回成功但没有边界时显示无需压缩，例如历史不足。失败不切新会话。

## 回执与卡片

接受的输入添加临时 `OnIt`，表示已接收或正在处理，不表示已经成功。成功结果且最终回复确实送达后，移除临时表情、添加 `Done`。失败、取消、停止和交付不明确时只清理临时表情；重启也会清理遗留的处理中标记。

表情更新按消息串行维护目标状态，完成不会被晚到的“处理中”覆盖。只删除本应用的表情，不删除其他机器人或用户的表情。表情 API 故障不阻塞 CC；重试不会重做任务。

一个回复周期共用一张卡片，引用本轮最初触发消息，不随最新补充者漂移。思考与答案分区，思考默认折叠、可展开查看；公开内容块按原生消息／块标识去重，不展示思考签名、不可展示块和工具调用轨迹。没有思考内容时不额外生成。审批与追问仍保留交互卡。

本轮结果合并消费多条输入时，按原生 UUID 分别完成这些消息的回执，不假设一条输入对应一个结果。多图批次映射回每张原消息，不仅标记批次入口；补充不另外生成 Agent 答案卡。后台输出只使用可靠的任务来源关联，未知来源不会随意挂到最新发言上。“已启动监控”的完成标记仅表示本轮回复完成，不表示监控任务已结束。

最终答案和合并卡片先落入 outbox，再进行网络更新。更新失败重试同一消息 ID；消息创建超时且结果不明时不盲目创建第二份，可从 `/outputs` 查看并显式补发。超长答案受卡片容量限制，正文另附文件；完整正文、文件目标和发送状态一起持久化。只有卡片与必要文件均确认送达，才标记 Done。附件按触发来源归属到轮次：只有与回复共享来源的未完成文件才阻塞该回复；回复没有来源记录时保守按会话等待，更早轮次明确失败的附件保留在 `/outputs`，不阻塞后续回复。文件发送失败或结果未知时，卡片尽力显示未完整送达，`/outputs` 保留文件阶段的补发记录。重启后可从持久正文重新生成文件；不会为补发重新请求模型，已经记录成功的文件也不重复发送。状态未知的文件发送只接受显式补发决定。

逐条输入取消只接受经输入锁和派发锁共同证明尚未交接的 queued 项目；图片批次整体处理。已提交和未知结果不伪称可撤回。逐条输出放弃沿可核实的来源关联同轮依赖，原子保存放弃决定及已知卡片的收尾交付；后到的原生最终回复继承来源标记。已在途交付不能与放弃并发提交，晚到预览 ACK 的卡片目标也持久保存。放弃不停止原生任务、不撤回远端消息、不设置 Done，且保留未知文件结果证据。

审批转发只有至少一张维护者卡片被平台确认后，才提示已发送；全部失败时按未送达拒绝请求，不把排队发送当成维护者已收到。

## 会话配置与快捷操作

命名模型配置属于当前会话；群内只有维护者可更改，私聊本人可管理。切换保持原生 ID，不改变端点、凭据、目录或工具权限。忙时保存选择，审批、后台与前台工作结束后再应用；新前台输入等待，合法补充仍交给原轮次，不越过 compact 或终止未确认的进程。

卡片预算按实际嵌套 JSON 字节数计算。审批与追问等待暂停回复卡流式状态但不标终态；答复继续原卡。预览曾明确失败并暂停更新时，进入等待仍尝试一次状态更新；再次明确失败则保持暂停。平台明确流过期或关闭时，仅对已有实体全量更新。停止和重启保留可恢复的旧卡收尾记录。

紧凑回复卡的顶部状态行随交付状态一同更新：文件待送达、未完整送达、取消或放弃时，不保留此前“已回复”或“处理中”的状态。恢复已保存的旧版卡片时兼容原有布局；状态刷新仍遵守同一卡片写入顺序与完整交付确认规则。

暂时限流尊重服务端等待时间并限制自动尝试次数；月配额耗尽等永久拒绝暂停自动重试。消息 UUID 与请求内容冻结，CardKit 创建、文件上传和消息发送分别确认。UUID 一小时去重窗口不保证恰好一次，不允许据此自动重放未知写入。`/outputs` 和补发按钮仅处理保存的输出，此前可能已被接受时仍需核实。

快捷操作重新验证房间、作者、实际卡片 ID、当前会话、轮次／输出版本和期限。旧卡不能停止后续轮次，补充表单无目标时不启动新任务，回答入口不能批准权限。已完成文件只在本房间保留期内取回；路径或授权失效时拒绝，不启动原生进程。手动重新取回产生独立文件交付记录；它失败或结果未知时，不会被当作后续模型回复的必需附件，也不会因此阻止后续回复标记 Done。

## 使用量

只展示实际原生 CLI 报告的所选会话用量；主循环 `result.usage` 的 input、output、cache read、cache creation 分开统计，不含子代理的独立用量。字段缺失为未知／null，不填零；模型来自实际响应元数据，不用配置别名猜测，多模型结果不擅自分摊。

按原生结果 ID 持久去重，重复结果、重启和安全输出补发不重复累计。统计起点、历史缺口和无法识别的结果显式披露，不把旧审计伪装成完整累计。没有稳定结果 ID 时不猜造去重键，当前未返回结果的消耗也未知。累计不是上下文占用或费用，不调用新模型、不扫描 transcript、不建立网关压缩器。[字段说明](usage.md#使用量)

## 升级

旧配置若显式设置 `backgroundMessages: 30`，修改默认值不会替它改成 0，应按部署需要改为 0。没有 `members` 的群现在只允许维护者；需要普通成员时填写明确的用户 ID。图片合批新增字段均可省略，缺省仍关闭，不修改旧配置的发送节奏。`groups[].mentionOptional` 也可省略，缺省仍要求明确 @。

未交付的背景在恢复时按新配置移除，待投递输入重新校验作者。已经进入旧 CC transcript 的内容不会因关闭背景而消失，本版本不擅自清空会话。需要干净上下文时显式 `/new`。

SQLite schema 5 保持既有会话命名空间，通过附加表及可缺省列保存交付日志、卡片生命周期、会话偏好与快捷控件绑定，不删除旧表或改写 session 映射。用量记录与覆盖起点沿用原语义，旧会话此前用量未知，不回填不可靠计数。升级前备份 `dataDir` 并停止旧服务，不并行运行两个实例操作同一状态库。切勿用删除状态目录来完成升级。
